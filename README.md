# agent-memory-bench

给「AI 的记忆能力」做一套公平的考试。

> **⚠️ 当前状态：两档八类跑得通，接了第一个真系统和第一个公开题库。**
> ⛔ 但题量还小，被测系统只有一个——现在的数字证明机制，不是评测结果。

## 为什么要做

各家记忆系统都说自己第一，但没法比——**同一个系统、同一份数据集，三家测出 84% / 58.44% / 75.14% 三个数。**

问题不在题不够多，在三件事没分开：

| | 现状 | 后果 |
|---|---|---|
| 「做不到」与「做错了」 | 记成同一个 0 分 | 没这功能的系统，和有功能但做砸的系统，读者分不出来 |
| 「我们的尺子」与「大家的尺子」 | 各家自己重写判分 | 分数没法跟别人比 |
| 「记忆层的活」与「生成器的活」 | 只报端到端准确率 | 把别人的 backbone 算进自己的成绩 |

## 三个核心主张

### ① 别人考过的，用别人的卷子和判分

15 个公开题库已经覆盖了检索质量、冲突消解、诚实弃权、记忆幻觉。
这些**一律调用它们、用它们的判分代码**。

自己重写一份只会引入「我们的判分与别人不同」这个不可比性。
上游判分有已知缺陷也照用——**把缺陷写进报告，而不是偷偷修好**。

### ② 只补别人结构上考不了的八类

分两批，来自两条独立的推导。

**翻遍公开题库，发现这四个漏洞：**

| | 考什么 | 为什么别人考不了 |
|---|---|---|
| **N1** | 世界变了，你发现没有 | 公开题库全是静态语料，没有可被求值的"现在" |
| **N2** | 你说这条来自 X，X 真是来源吗 | 现有接口没有"出自原文哪一段"这一维 |
| **N3** | 结论蒙对了，但推理每一步站得住吗 | 只判最终答案，蒙对满分 |
| **N4** | 谁写的、谁能读、删了留痕吗 | 现有接口 `ask(question)` 不带"谁在问" |

**再从人的记忆规律反推一遍，又发现四个：**

| | 考什么 | 为什么别人考不了 |
|---|---|---|
| **N5** | 该记的记住了，**该忘的忘了吗** | 静态语料里不存在"间隔"，也不存在"未来" |
| **N6** | 关联多了更好找，还是更找不准 | 自然语料的图拓扑是碰巧长成的，不可控 |
| **N7** | 它知不知道自己什么时候会错 | 弃权全是二元的，接口里没有置信度这个出口 |
| **N8** | 归纳出规律后，遇到例外会不会把规律整个扔了 | 没有题库提供带例外的、有统计规律的世界 |

⭐ **两条推导独立地指向了同样的前四类**——这是对这套设计最强的支持。

⚠️ 反推时本来还找到第五个缺口「虚构」，核实后发现
[HaluMem](docs/benchmarks.md) 已经覆盖了，于是**没有立类**。
「能用别人的尺子就用别人的」在那里省掉了一整个套件。

### ③ 「做不到」和「做错了」必须分开记

大多数系统在后四类会答「我没这功能」。⛔ **那该记成「不支持」，不是 0 分。**

实际有三种结果，判分位置各不相同：

| | 计入分母 | 在表里 |
|---|---|---|
| **不支持** — 没这功能 | ❌ 否 | 独立一列，不参与排名 |
| **失败** — 有功能但这次没做成 | ✅ 是 | 计入分数 |
| **做错** — 做了，答案不对 | ✅ 是 | 计入分数 |

任意两种合并，这把尺子第一天就废：
把「不支持」和「做错」混起来，会让人以为这几类是我们编出来给自己送分的；
把「失败」和「不支持」混起来，则开了个后门——声明全部能力、次次失败，就换到一个永不掉分的位置。

### ④ 每个分数都要跟着「不装它是多少」

一个系统在某题上拿 72%——这是好是坏，取决于不装它是多少分。
所以每批结果都跟着[五条对照组](docs/baselines.md)一起跑：

| | 是什么 |
|---|---|
| **无记忆** | 只给当前轮，什么都不留 |
| ⭐ **裸宿主** | 不挂记忆插件，只用 agent 自带的上下文压缩——**这才是真实地板** |
| **朴素 RAG** | chunk + embedding + top-k，就这样 |
| **BM25** | 连 embedding 都不要 |
| **全上下文** | 全部塞进窗口——天花板参照 |

⛔ **绝对分不单独报**，必须给出相对地板的增量和贵了几倍。
跑不赢「让 agent 自己压缩上下文」的记忆系统，是在添麻烦。

⭐ 有一处会反直觉：**N1（世界变了你发现没有）的地板线可能接近满分**——
一个不记东西的 agent 每次都重读文件，永远看到当前世界。
这不是 N1 出错了，恰恰说明它在问什么：**记忆带来速度，也带来过时风险。**

## 怎么保证公平

**不用 AI 当评委。** 自研的八类全部确定性判分——评委模型换一个分数就飘，
而这要当长期可比的尺子。（公开题库那边照用它们自己的判分，包括它们的评委。）

**只走公开接口。** ⛔ 这条**首先管我们自己的系统**。
一个能伸手进自己人内部的评测框架，公正性没法自证——而这个项目的全部价值就在于它能自证。

**协议只说要回答什么，绝不说怎么做到。** 比如要求系统提供「断言」，
那就是照着某一家的实现写的——有断言的赢，没有的输，而输的原因是接口偏心，不是能力差。

**同一个 agent，只换记忆。** 把被测系统装进同一个 agent 宿主
（[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)）里跑，
backbone、工具集、循环全部钉死，agent 成为受控变量。
不这么做，测的就只是记忆库，那不叫 agent memory。

**⭐ 快慢是一个维度，不是脚注。** 一个什么都记得住但慢得要死的系统没有用——
用户要个东西等半天，那还不如不记。所以成本与质量并排判：
⭐ 又快又好 / ⚠️ 更准但更贵 / ⛔ 被地板压制 / ⛔ 慢到不可用。
⛔ 不合成总分——权衡因用途而异。

**利益关系全标出来。** 题库是被测方维护的、适配器是被测方提交的、被测系统是我们自己的——
[全部标注](docs/report.md)，读者自己判断。

## 现在到哪了

```
docs/     设计文档
src/      九层实现 —— 八类题全部跑得起来
tests/    226 项断言，全绿
```

```sh
python -m amb.cli setup                    # ⭐ 一键装外部依赖，钉死版本
python -m amb.cli                          # 直接调库，五条对照组
python -m amb.cli --lane agent --arms bm25 # 装进 agent 跑
python -m amb.cli --bench locomo --sample stratified:50 --max-convs 2 \
                  --arms bm25,mem0         # 公开题库 + 抽题
```

**抽题**：`all` · `first:N` · `random:N` · **`stratified:N`** · `ids:a,b`，
⚠️ `--max-convs` 另外控**语料量**——⛔ 与题数是两件事
（对每条都调 LLM 的系统，语料量才是那个约束）。

**目录结构是写死的，依赖关系是测试断言，不是文档约定。**
[`architecture.toml`](architecture.toml) 说了算，
[`tests/`](tests/) 强制执行——每一条我都注入过违规，确认它真的会红。

架构是照着现有框架的毛病反着设计的。以覆盖面最广的 MemoryData 为例，实测：

| 它的问题 | 我们的对策 |
|---|---|
| 把上游整包抄进仓库，**36.7 万行 / 2358 个文件** | 适配器薄度上限，测试拒收上游构建文件 |
| 用 `if "mem0" in 名字` 分发，而它同时有 `mem0` 和 `amem0` | 注册表只做精确匹配 |
| `utils/` **8006 行**，单文件 4569 行 | 没有 `utils/`；每个包必须写清"只干哪一件事" |
| 兄弟模块反向依赖，一个基准成了所有人的地基 | 分层，用 AST 检查 import 方向 |
