# N4 · 治理可审计性

## 考什么

**谁写的 · 谁能读 · 删除之后审计轨迹是否留存。**

## 为什么公开题库测不了

现有适配器接口里**没有主体**——`ask(question)` 不带"谁在问"。
所以任何权限、归属、问责的问题都无法表达。

这不是疏漏，是这批基准的假设：它们假设记忆系统服务单一用户。

## 一个必须先解决的矛盾

[原则④](../adapters/README.md#p4)禁止伸手进被测系统内部。
但黑盒之下，「内容有没有被**彻底**删除」是观察不到的——
你只能看到 `search` 不再返回它。而这恰恰是本文下面要批判的那件事：
**过滤不等于删除**。同一套推理用在删除上，第三组就根本判不了。

裁决：**给原则④开一个受限的例外，并写死它的边界。**

| | 做法 |
|---|---|
| 通道 | `storage_locations() -> list[str]`，由适配器**自己申报**持久层位置 |
| 权限 | harness **只读**打开这些位置，不解析内部结构，只做全文/二进制子串搜索 |
| 范围 | ⛔ 只在 N4 的删除组使用，其他任何套件不得触碰 |
| 不申报时 | 记 **部分支持**——删除组只出「过滤层」结论，⛔ **不得记为通过** |

「申报」这个形状是刻意的：它不是 harness 去猜内部结构，而是被测方声明
「我的数据在这里，你去查」。查不查得到不由被测方控制，但查哪里由它划定——
这样既不需要理解内部实现，也不算伸手进去。

## 判分

确定性。四组：

| 组 | 判什么 |
|---|---|
| 归属 | 每条记忆说不说得出**谁写的**、何时、从哪来 |
| 隔离 | 主体 A 的记忆，主体 B 问的时候会不会返回 |
| 删除 | 内容能否**彻底删除** |
| 留痕 | 删除之后，**审计轨迹是否还在**（删了什么、谁删的、何时） |

后两组是一对：**能删但不留痕**和**留痕但删不掉**都不合格。

### 隔离：过滤还是授权

⚠️ 行业现状是「隔离全是过滤，不是授权」——多数系统的 scope/user_id 是查询过滤字段，
绕开查询接口就没有约束。判分要能区分这两者，用三级：

| 级 | 判据 |
|---|---|
| **无隔离** | `search(principal=B)` 直接返回了 A 的条目 |
| **过滤级** | 走 `search` 时隔离成立，但带外只读能在持久层读到 A 的明文 |
| **授权级** | 带外只读也读不到 A 的明文（加密 / 物理分库 / 行级安全） |

未申报 `storage_locations()` 的系统**最高只能记到「过滤级（未验证）」**。

### 删除：四步探针

单发一次 `delete()` 再 `search` 一下，只能测到过滤层。四步，逐步加压：

1. `delete(ids)` → 读 `DeleteResult.deleted` / `refused`
2. `search` 同一 query → 被删条目不应返回
3. **重开**：`close()` → 重新构造适配器 → `setup(world)` → `search` 再查一次
   ——⚠️ 这一步专门抓**内存里的过滤**，重启即现原形
4. **带外**：在 `storage_locations()` 申报的位置里搜被删内容的特征子串

四步全过才是「彻底删除」。任一步止步，报到那一步为止，**不四舍五入成通过**。

### 留痕与删除的交叉

删除组与留痕组必须**交叉判**，不能各判各的：

| | `audit_log` 里有删除事件 | 没有 |
|---|---|---|
| **四步探针全过** | ✅ 合格 | ❌ 删得掉，但没人知道删过 |
| **未彻底删除** | ❌ 留了痕，但内容还在 | ❌ 两头都不合格 |

⛔ `audit_log` 本身**不得**因为 `delete()` 而消失对应记录——那就是留痕失败。
反过来，`audit_log` 里若还含有被删内容的**正文**，删除组判不通过：
把内容藏进审计日志不算删除。

## harness 需要能做什么

- 以不同主体身份发起写入（`Document.principal`）与查询（`search(principal=…)`）
- 发起删除请求，之后分别检查内容与审计轨迹
- **重开适配器**（`close()` → 重建 → `setup()`），用于删除探针第 3 步
- 对 `storage_locations()` 申报的位置做只读子串搜索

## 不支持时

绝大多数开源记忆系统在这一类上会报 **不支持**。这是意料之中的，
也正是这一类值得存在的原因——**它衡量的是一个没人在衡量的维度**。

⚠️ 注意 N4 有「部分支持」这一档（未申报 `storage_locations()`），
它既不是不支持也不是通过，在[报告](../report.md)里单列。
