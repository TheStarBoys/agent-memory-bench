# N4 · 治理可审计性

## 考什么

**谁写的 · 谁能读 · 删除之后审计轨迹是否留存。**

## 为什么公开题库测不了

现有适配器接口里**没有主体**——`ask(question)` 不带"谁在问"。
所以任何权限、归属、问责的问题都无法表达。

这不是疏漏，是这批基准的假设：它们假设记忆系统服务单一用户。

## 判分

确定性。四组：

| 组 | 判什么 |
|---|---|
| 归属 | 每条记忆说不说得出**谁写的**、何时、从哪来 |
| 隔离 | 主体 A 的记忆，主体 B 问的时候会不会返回 |
| 删除 | 内容能否**彻底删除** |
| 留痕 | 删除之后，**审计轨迹是否还在**（删了什么、谁删的、何时） |

后两组是一对：**能删但不留痕**和**留痕但删不掉**都不合格。

⚠️ 行业现状是「隔离全是过滤，不是授权」——多数系统的 scope/user_id 是查询过滤字段，
绕开查询接口就没有约束。判分要能区分这两者。

## harness 需要能做什么

- 以不同主体身份发起写入与查询
- 发起删除请求，之后分别检查内容与审计轨迹

## 不支持时

绝大多数开源记忆系统在这一类上会报 **不支持**。这是意料之中的，
也正是这一类值得存在的原因——**它衡量的是一个没人在衡量的维度**。
