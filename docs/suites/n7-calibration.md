# N7 · 置信度校准

## 考什么

**系统说自己有多确定的时候，那个数字可信吗。**

不是「答得对不对」，是**「它知不知道自己什么时候会错」**。

## 为什么公开题库测不了

**这是接口级的缺失，不是碰巧没测。**

弃权这一维公开题库覆盖得不错——[LoCoMo 有 22% 的弃权题](../benchmarks.md)、
BEAM 有专门的 Abstention 能力。但**它们全都是二元的**：

| 题库 | 现状 |
|---|---|
| BEAM | Abstention = "withholds answers when evidence is missing"，答或不答 |
| HaluMem | 六种题型全部二元对错判分 |
| LoCoMo | 弃权题只判「有没有拒答」 |

**没有任何公开题库的接口让系统输出分级置信度**，所以 ECE、Brier、
可靠性图这些东西无处可放。⛔ 这不是「别人碰巧没做」，
是**它们的接口里没有这个出口**——加数据集补不上。

⚠️ 「虚构」那一半**不在这一类里**：HaluMem 的 `Memory Boundary` 题型
已经在测「编造没说过的事」，按纪律不重复造。详见
[`../cognition.md`](../cognition.md#gaps)。

## 判分

确定性。系统对每个回答给出 `confidence ∈ [0, 1]`，含义固定为
**「这个回答正确的概率」**。

⚠️ **`confidence` 不是 `Entry.score`。** score 是相关性排序分，
量纲和语义都由系统自定；confidence 是一个有外部含义的概率。
两者混用会让校准分变成对排序分的重新缩放。

### 三个指标

| 指标 | 说明 |
|---|---|
| **ECE**（期望校准误差） | 按置信度分桶，每桶内 \|平均置信度 − 实际准确率\| 的加权平均 |
| **Brier 分数** | 逐题 (confidence − 对错)²，同时含校准与区分度 |
| **可靠性图** | 每桶的置信度 vs 准确率，⭐ **必须与两个数字一起给** |

⛔ **不要只报一个 ECE。** ECE 对分桶方式敏感，而且**低 ECE 可以靠
把所有置信度压到基准准确率附近取得**——那样的系统校准很好、
但完全没有区分能力。可靠性图能一眼看出这种退化，两个标量不能。

⚠️ 同时报**区分度**（置信度高的组与低的组之间的准确率差）。
校准与区分度是两件事，缺一个都能被刷。

### ⭐ 显著性子测：自信但不更准

这一组是这一类里最值得做的，因为它对着一个**已知的、可复现的失效模式**。

**闪光灯记忆**（Talarico & Rubin 2003）：高情绪唤起事件的记忆
**准确度衰减速度与普通记忆相同**，但生动度、信心、
「相信自己记得准」**不衰减**。用原文的说法——
这类记忆**不是更准，只是自觉更准**。

所以出题：

```
世界里标记一批「后果重大」的事件（与普通事件的频率、间隔匹配）
推进模拟时间
在同一个保持间隔上，对两类事件分别测 准确率 与 置信度
```

| 观察 | 判定 |
|---|---|
| 显著事件准确率更高、置信度也更高 | ✅ 显著性确实带来了更好的巩固 |
| 准确率相同、**置信度更高** | ❌ **复现了人类的 bug** —— 扣分 |

⛔ **这一次我们知道它是 bug，所以扣分。** 这是
[「人的记忆不是标准答案」](../cognition.md)在判分上的一次具体落地：
像人不是加分项。

## 评测器需要能做什么

- 拿到每个回答的 `confidence`（`Answer.confidence` / `Entry.confidence`）
- 世界能标记事件显著性，且**显著性与频率、间隔正交**
- 在同一保持间隔上分组对比准确率与置信度

世界的要求见 [`../adapters/world.md`](../adapters/world.md#事件流与统计结构)。

## 不支持时

**大多数系统会报不支持**——它们返回排序分，不返回「我有多确定这是对的」。

⚠️ ⛔ **不得拿 `Entry.score` 顶替。** 把排序分当置信度算出来的 ECE
是个没有意义的数字，比不支持更糟——不支持是诚实的，顶替是伪造了一个维度。
声明 `CONFIDENCE` 的系统必须给出概率语义的数值。
