# N1 · 对现实求值

## 考什么

**外部现实发生了变化，系统能否发现某条记忆已经不再成立**——
最好是在没人问的情况下自己标出来。

## 为什么公开题库测不了

15 个公开题库全是静态语料：喂一段对话、问一个问题、比对答案。
**没有任何一个提供可以被改变、并被系统求值的"现实"。**

最接近的是 [STALE](https://arxiv.org/abs/2605.06527)（400 个专家校验的冲突场景），
但它测的是**模型能否识别隐含状态变化**，不是**系统能否对外部状态求值**。
它自己也明说只覆盖对话历史，不处理外部来源的新鲜度。

STALE 顺带命名了这个现象，值得抄在这里：

> **recognition does not imply application** —— 识别出"过时"得 76%，
> 下游真的用新状态掉到 **39%**（*current-state adjudication gap*）。
> 最好的模型总分 **55.2%**。

## 两种

评测器改完世界之后**不通知任何人**（[world.md](../adapters/world.md#变更不通知)）。
从这里分出两种，**分开报，永不合并**：

| | 评测器行为 | 系统从哪表态 | 量的是 |
|---|---|---|---|
| **有提示** | 调 `audit(claims)`，把命题交过去 | `Verdict.state` | 给了机会，你查得准不准 |
| **无提示** | 不调 `audit`，只发 `search` | `Entry.state` + `Entry.doc_ids` | 没人提醒，你自己发现了吗 |

⭐ **这两种确实区分得开系统**，不是纸上分类：一个只在 `audit()` 里认真、
`search()` 从不表态的系统，有提示满分、无提示零分。
两种给出同一个数才说明这一档白设了。

⚠️ **有提示由评测器出命题，不是让系统列举「我的哪些记忆坏了」。**
后者预设系统持有可枚举的离散条目集合，是对参数化记忆（MemoryLLM）、
摘要树（raptor）的形状歧视——理由见
[protocol.md · 为什么 audit() 由评测器出命题](../adapters/protocol.md#why-evaluator-issues-claims)。
「主动」这一维由无提示承载，没有丢。

## ⭐ 实测：agent 档为什么要两轮

第一版让 agent 在一轮里既去核实又记得调表态工具，实测漏提交率
33%–100%（工具越多越分心：bm25 有记忆工具，0/3），
Failed 率超过 20% 直接把整档打成 `untrusted`。

⚠️ 那测的是**指令遵循**，而 backbone 对所有臂相同——是噪声不是信号。

改成两轮（第一轮自由核实，⭐ 第二轮只干提交这一件事）之后：

| | 状态 | 需提醒率 |
|---|---|---:|
| `host_default` | ✅ scored | 33% |
| `bm25` | ✅ scored | 67% |

⭐ 同样的漏提交现象还在，但它现在是**一个可读的数字**，
而不是把整档打掉。⛔ 需提醒率不进主指标——它量的是指令遵循，不是记忆能力。

## 判分

确定性，不需要 LLM 评委。

### 三态

| 判定 | 含义 |
|---|---|
| `holds` | 命题对当前世界仍然成立 |
| `broken` | 已经不成立 |
| `unknown` | 系统没能判定，**并列出没能核到的是什么** |

⚠️ **命名上避开了 `pass` / `fail`**，虽然那是更顺口的一对。原因是
在这一类题里，「检出了腐化」是**好**结果——叫它 `fail` 会让整张判分表反着读；
而 `Failed` 在[协议](../adapters/protocol.md#三态返回)里已经表示
"声明了能力却没做成"，是**坏**结果。同一个词两个相反的含义，判分表迟早写错。

### 六格全报

⛔ **`unknown` 折进 `holds` 或 `broken` 都是作弊。**

但光有这一句不够——还得说清三态**怎么聚合成一个可报的数**。
如果只报检出率和误报率，`unknown` 在这两个率里都不出现，
于是一个对所有命题都回 `unknown` 的系统检出率 0、误报率 0，
在表里看起来比一个有真实误报的系统更"干净"。

所以判分口径是一张 **3×2 混淆矩阵，六格全部进报告**：

| | 上报 `holds` | 上报 `broken` | 上报 `unknown` |
|---|---|---|---|
| **真值：仍成立** | ✅ 正确保留 | ❌ **误报** | ⚪ 弃权 |
| **真值：已失效** | ❌ **漏检** | ✅ **检出** | ⚪ 弃权 |

派生指标一律从这六格算出，且**必须三个一起出现**：

```
检出率 = 检出 / (检出 + 漏检 + 失效侧弃权)
误报率 = 误报 / (正确保留 + 误报 + 成立侧弃权)
弃权率 = (两侧弃权) / 总数
```

⚠️ **弃权进分母。** 不进分母的话，弃权就成了免费的避险动作——
不确定就回 `unknown`，检出率和误报率都不受影响。
弃权是诚实的，但不是免费的。

### `unknown` 的理由怎么确定性判

`Verdict` 有两个说明字段，判分只看其中一个：

- `grounds: list[str]` —— 结构化依据：世界内路径 / 事实表键 / `Entry.id`。**判分读这个。**
- `note: str | None` —— 散文。**判分不读。**

评测器只做两件事：`grounds` 非空，且每一项都解析得到。
⛔ 空 `grounds` 判为 `Failed`，不是 `unknown`。

这样「必须说清为什么」就是可确定性判分的。让判分去读散文，
就等于把 LLM 评委请回来了，而[约束①](README.md)不允许。

## 🔜 一个还没测的机制：拿旧记忆作答

⭐ 实测顺带撞见的：世界里那份笔记被删了之后，一个有索引的系统
**照样能从摄入时留下的旧块里答出来**，而且答得很自信。
一个没有记忆的系统反倒诚实地说「资料未提及」。

这不是 `audit()` 测得到的——它问的是「你知不知道自己过期了」，
而这里问的是「你会不会**用**过期的东西去回答」。
[STALE 给这个现象起过名字](https://arxiv.org/abs/2605.06527)：
**recognition does not imply application**，识别得出 76%，下游真用新状态掉到 39%。

⚠️ **不要把它塞进 QA 的「编造率」**：那一列的含义是「语料里从来没有的东西你编了」，
混进「后来被删了」会让一个数含两种成因，读不出是哪一种。
它该是 N1 下的第三种探针，题面与判分待定。

## 评测器需要能做什么

- 在两次询问之间**改变外部世界**——文件树、事实表、时钟三样
  （[`WorldHandle`](../adapters/protocol.md#世界句柄)）
- 出命题（`Claim`），并且知道每条命题的真值与它源自哪些 `Document`
- 读到 `Verdict.state` / `Verdict.grounds`（有提示）与 `Entry.state` / `Entry.doc_ids`（无提示）

## 不支持时

绝大多数系统没有对现实求值的能力。它们应当报 **不支持**，不是 0 分。
见 [三条设计约束②](README.md)。

⚠️ 无提示另有一条独立的不支持判据：`Entry.doc_ids` 为空的系统在无提示的情况下记**不支持**——
不是它答错了，是评测器无从把它标 `broken` 的条目对回被破坏的那个事实。
