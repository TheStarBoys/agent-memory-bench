# 适配器协议

> **状态：草案。尚未实现。** 定下来之前不要开始写适配器。

## 为什么不能用现成的接口

现成 harness 的适配器是五个方法：

```python
add_chunk(content, timestamp)   finalize()
ask(question) -> str            retrieve_entries(question)   memory_count()
```

**它把记忆系统当纯函数**：喂进去、问出来、比对字符串。
[公开基准](../benchmarks.md) 全是这个形状，所以它够用。

[自研四类题](../suites/README.md) 一类都塞不进去，因为它们问的不是"你答得对不对"：

| | 需要什么，而五方法接口没有 |
|---|---|
| N1 对现实求值 | 一个 **harness 能改变的外部世界**，以及"哪条命题不再成立"这个出口 |
| N2 原文回链 | 条目上的**来源区间**（起止），而 `retrieve_entries` 没有这一维 |
| N3 推理链 | **结构化的推导链**，而 `ask` 只返回字符串 |
| N4 治理 | **主体**——`ask(question)` 不带"谁在问" |

**这不是加参数能补的，是接口的假设不同。**

## 六条原则

<a id="p1"></a>

### 原则① 能力自述，不靠试错

适配器**预先声明**支持哪些能力，harness 只跑声明过的套件。

没声明的记成 **不支持**，进独立的列，**永远不折进 0 分**。
把"做不到"和"做了但做错"记成同一个数，这把尺子第一天就废了
（[设计约束②](../suites/README.md)）。

#### ⚠️ 这条会催生一个反向漏洞，必须一起堵上

「不支持」不计入分母，于是**声明一个能力只可能让分变难看，从不会让它变好看**。
理性的适配器作者会尽量少声明——一个本来能勉强做 N2 的系统，
不声明 PROVENANCE 就能躲开一列不好看的数字。

**「不支持不计 0 分」和「少声明占便宜」是同一枚硬币的两面**——
只防前者、不防后者，等于把作弊的方向换了一个而已。三条一起堵：

| 手段 | 做什么 |
|---|---|
| **参与面进报告** | 分数旁边并列「声明了几项 / 参与了几题」，沉默本身可见（[`../report.md`](../report.md)） |
| **`Failed` 计入分母** | 声明了却次次做不成，不能换到一个免罚的位置（[protocol.md · 三态返回](protocol.md#三态返回)） |
| **声明进结果快照** | 每次跑的能力声明随报告发布；后续撤销要写明理由 |

⚠️ 冒烟检查只能验「不支持被正确记录」，**验不出谎报不支持**。
这是这套协议的已知残余风险，靠参与面曝光，不靠检测。

<a id="p2"></a>

### 原则② 机制中立：协议只说要回答什么，绝不说怎么做到

⛔ 这是**防主场优势的唯一手段**，也是最容易破的一条。

反面例子：如果 N1 的协议要求系统提供「断言」，那它就是照着某一家的实现写的——
有断言的系统赢，没有的输，而输的原因是接口偏心，不是能力差。

**正确的形状是给一个任务，不是给一个机制**：
> 这是一个世界。这些对话陈述了关于它的事实。世界随后变了。
> **下面这些说法，哪些已经不再成立？**

重读文件、调模型、跑断言、什么都行。harness 只看答案。

#### ⚠️ 这一条最容易在自己手里破掉

举一个差点写进本协议的反例：让 `audit()` 不带参数，
由系统返回「我的哪些记忆不再成立」。听上去只是在问结果、没问机制——
**但它预设了系统持有可枚举、有稳定 id 的离散条目集合**，
而 MemoryLLM（参数化记忆）、raptor（递归摘要树）没有这种集合。
拿「不要求提供断言」当反面例子、同时在自己的接口里要求一个可枚举的条目集，
是同一种形状偏心换了层皮。

所以定稿是 **harness 出命题**：`audit(claims)`。系统只回答"这句话现在还成不成立"，
内部怎么存不影响它能不能参赛。**「主动发现」这一维交给
[自发档](world.md#两档)承载，没有丢。**

⚠️ 这一条要反复自查，判据只有一条：**换一种内部实现，这个接口还接得上吗？**

<a id="p3"></a>

### 原则③ 世界归 harness 所有，适配器只读

被测系统**不得修改**世界。否则"通过"可以靠改变现实取得。
世界的构造与变更见 [`world.md`](world.md)。

⚠️ 光靠事后哈希校验不够，那是取证不是防护——
文件树只读挂载、时钟与事实表只开 `GET`，见
[world.md · 强制，而不只是检测](world.md#强制而不只是检测)。

<a id="p4"></a>

### 原则④ 只走公开接口

适配器通过**用户能用的方式**调用被测系统。

⚠️ **判据是「公开与否」，不是进程边界。** 写成「只走进程外接口」会出两个问题：
它把 SDK 排除在外（SDK 是进程内的），而被测名单里有一批
（A-mem · raptor · self-rag · langmem · MemoryLLM）**只有 import 这一个入口**，
按那个说法就全都接不进来。

| 允许 | HTTP API · CLI · 包顶层导出的 SDK · 上游 README/文档里记载的调用方式 |
|---|---|
| ⛔ 禁止 | import 未文档化的子模块 · 直接读写它的存储 · monkey-patch · 复制它的内部代码 |

⛔ **这条对本项目作者自己的系统同样成立，而且首先针对它。**
一个能伸手进自己人内部的评测框架，公正性没法自证——
而这个项目的全部价值就在于它能自证。

#### 唯一的例外：N4 删除组的带外只读取证

黑盒之下「内容有没有被彻底删除」观察不到——你只能看到查询不再返回它，
而那正是 N4 要批判的「过滤不是删除」。所以开一个受限例外：

适配器**自己申报** `storage_locations()`，harness 在这些位置做**只读子串搜索**，
不解析内部结构。⛔ 只在 N4 删除组使用。不申报的记「部分支持」，不记通过。
细则见 [N4 · 一个必须先解决的矛盾](../suites/n4-governance.md#一个必须先解决的矛盾)。

<a id="p5"></a>

### 原则⑤ 确定性判分，自研套件不用 LLM 评委

评委模型一换分数就漂。公开的 J 分已有前车之鉴：同一系统、同一数据集，
**84% / 58.44% / 75.14% 三个数**。

公开基准那边照旧用它们自己的判分代码——那是"同一把尺子"的前提。
上游判分本身有缺陷时怎么办，见
[harnesses.md · 上游判分坏了怎么办](../harnesses.md#上游判分坏了怎么办)。

⚠️ 这条给 N1 与 N3 各留了一道坎，都已在套件文档里裁决：

- **N1** 要求 `unknown` 说明原因，而理由是散文 → 改为结构化 `grounds`，判分不读散文
- **N3** 要求判每一步是否成立，而自由文本推理步骤只有评委判得了 →
  **语料改为合成**，claim 是三元组、rule 取自封闭词表，代价是测不到自然语言推理

<a id="p6"></a>

### 原则⑥ 成本与延迟是一等指标

摄入 token、查询 token、墙钟时间，逐阶段记录。

一个赢 2 个百分点但贵 10 倍的系统，不写下来就看不出来。

⛔ **没有任何公开题库把成本当一等指标**（核实 2026-09-01：BEAM 常被认为报了成本，
实际只报准确率——[详情](../benchmarks.md)）。这条是本项目独有的要求，
没有现成的可照抄，接口形状要自己定。

⚠️ **这条原则必须在接口上有落点，否则它只是一句口号。**
墙钟 harness 自己测得了，**token 测不了**——那些 LLM 调用发生在适配器内部。
所以协议里有 `usage() -> list[Usage]` 与 `Capability.ACCOUNTING`
（[protocol.md](protocol.md#数据类型)）。

⚠️ 墙钟**两份都要**：harness 从外部独立计时一份，适配器自报一份。
两者差得多本身就是信息（排队、重试、后台补偿）。

## 接一个新系统要做什么

1. 声明能力（原则①）——**少声明会在参与面上可见**
2. 实现基线七方法：`setup` `ingest` `finalize` `search` `count` `reset` `close`
   ——公开基准需要，**不得返回三态**
3. 按声明实现对应套件的方法
4. 遵守 [id 契约](protocol.md#id-契约)：不回收、归并留 `supersedes`、`mutate` 期间不漂
5. 钉死被测系统的版本号（[六个已停更的项目](../systems.md)尤其重要）
6. 跑冒烟，确认三件事：
   - 「不支持」被记成不支持，而不是 0
   - 「失败」被记成 `Failed`，而不是不支持
   - 适配器全程没有写过世界（哈希在四个阶段边界都一致）

接口定义见 [`protocol.md`](protocol.md)。
