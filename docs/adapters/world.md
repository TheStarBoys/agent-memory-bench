# 有状态的世界

> **状态：草案。** N1 依赖它。没有这一层，[对现实求值](../suites/n1-reality.md)
> 就退化成又一道阅读理解题。

## 它解决什么

公开题库是静态的：语料给定、问题给定、答案给定。
于是**「记忆是否仍然为真」这个问题根本无法提出**——没有"现在"，只有语料。

世界提供的就是那个"现在"：一份 harness 拥有、可以被改变、可以被系统读取的外部状态。

## 三样东西

它们通过 [`WorldHandle`](protocol.md#世界句柄) 在 `setup()` 阶段交给被测系统。

| | 是什么 | 系统怎么读到 |
|---|---|---|
| **文件树** | 一个目录，harness 物化出来 | `world.root` 下的路径 + 内容 |
| **时钟** | 一个可拨动的当前时间 | `GET world.clock_url` → `{"now": …}` |
| **事实表** | 键值对，代表外部服务/配置的当前取值 | `GET world.facts_url/{key}` |

三样都**足够朴素**是刻意的：世界越花哨，越容易长成某一家的实现形状，
而那正是[原则②机制中立](README.md#p2)要挡的东西。

⛔ **时钟与事实表必须是端点，不能是 `setup()` 时发过去的值。**
发一个时间字符串过去，系统就再也察觉不到时间流逝——
而时间流逝是下面五种变更之一。给端点，它才有机会去看；去不去看是它的事。

⛔ **三个端点都不推送。** 没有回调、没有事件、没有版本号跳变、没有 ETag。
想知道世界变没变，只能自己再读一遍。

## 归属与只读

**世界归 harness 所有。被测系统只读。**

一个能写世界的系统可以靠**改变现实**让自己的记忆重新为真——
那不是通过测试，是把考题改了。

### 强制，而不只是检测

⛔ **只在 `probe` 前后校验哈希是不够的**，两个理由：

- **窗口不对。** `ingest` 与 `finalize` 期间系统同样在运行、同样够得着世界。
  校验要**每个阶段边界各一次**（setup 后 / ingest 后 / mutate 后 / probe 后）。
- **校验是事后取证，不是防护。** 真正的保证来自权限：
  文件树以**只读挂载**（`mount -o ro` / 容器 `readOnlyRootFilesystem`）暴露；
  时钟与事实表只提供 `GET`，其余方法一律 405。

哈希不一致**直接判本次跑作废**，不是扣分。

### 哈希算什么

不能只哈希文件内容——时钟和事实表不是文件。世界哈希取自一份**规范化序列化**：

```
sha256(
  文件树：按路径字典序，每条 "路径\0mode\0内容sha256\n"
  时钟  ：当前 now（RFC3339，UTC，秒精度）
  事实表：按键字典序，每条 "键\0值\n"
)
```

⚠️ **mtime 不进哈希，但必须钉死**——见下一节。

## 变更不通知

`mutate` 阶段改完世界，**不告诉适配器**。

这是 N1 的全部要害：被告知"世界变了，去查一下"再去查，测的是**执行**；
没被告知还能发现，测的才是**主动检测腐化**。

### 两档

同一批题因此天然分两档，分开报：

| 档 | harness 行为 | 系统从哪表态 | 量的是 |
|---|---|---|---|
| **触发档** | 调 `audit(claims)`，把命题交过去 | `Verdict.state` | 给了机会，你查得准不准 |
| **自发档** | 不调 `audit`，只发 `search` | `Entry.state` | 没人提醒，你自己发现了吗 |

⛔ **自发档必须有自己的观测出口，否则判不了分。**
「不调 `audit`，看下次 `search` 的结果」这句话本身不构成一个出口——
如果 `Entry` 上没有字段能表达"这条已经不成立"，那唯一可观察的就是
**这条不再被返回**，而那与「排序变了」「k 不够」「被归并了」完全不可区分。

出口是 `Entry` 上的两个字段（[`Entry`](protocol.md#数据类型)）：

- `state` —— `holds` / `broken` / `unknown` / `None`（不表态）
- `doc_ids` —— 这条源自哪些 `Document`，harness 靠它把条目对回被破坏的事实

`doc_ids` 为空的系统在自发档记**不支持**：不是它答错了，是无从对账。

绝大多数系统在自发档上会全军覆没。**那是这一档的意义，不是它的缺陷。**

## 变更的类型

每一类对应一种真实的腐化方式：

| 类型 | 世界里发生什么 | 命题应当变成 |
|---|---|---|
| **消失** | 文件被删 | 依赖它存在的 → `broken` |
| **改值** | 文件内容 / 事实表取值变了 | 断定旧值的 → `broken` |
| **新增** | 出现了新文件 / 新键 | 多数命题不受影响 → 仍 `holds` |
| **时间流逝** | 时钟前推 | 带有效期的 → `broken` |
| **无关变更** | 改动与任何命题都无关 | **全部仍 `holds`** |

⛔ **最后一行是这套题的反方向，必须有。**
只考"该 `broken` 的有没有被标出来"，一个把所有东西都标成 `broken` 的系统会拿满分。
**误报率和检出率一起报，缺一个这一类就没有意义。**

判分的完整口径（3×2 混淆矩阵、六格全报）见
[N1 · 怎么判](../suites/n1-reality.md#判分)。

## 事件流与统计结构

上面那个世界是**一张快照加若干次变更**。它够 [N1](../suites/n1-reality.md) 用，
但 [N5](../suites/n5-consolidation.md) · [N7](../suites/n7-calibration.md) ·
[N8](../suites/n8-induction.md) 都用不了：
它们问的不是「世界变了你发现没有」，而是**「世界长期这样运转，你沉淀下了什么」**。

缺的不是更多变更，是**统计结构**。

| 已有 | 还需要 |
|---|---|
| 文件树 / 时钟 / 事实表 | **事件流**——世界按模拟时间持续产生事件，而不是一次性给定语料 |
| 一次性的 mutate | **频率**——有的事重复出现，有的只出现一次 |
| — | **间隔**——同一件事的复现间隔可控（集中 vs 分散） |
| — | **显著性**——哪些事件「后果重大」，⛔ **与频率、间隔正交** |
| — | ⭐ **需求概率**——每条事实未来被查询的概率分布 |
| — | **规律 + 例外**——成立率可控的统计规律，加明确的例外个例 |
| — | **可控的图拓扑**——实体关联度可调（[N6](../suites/n6-structure.md)） |

### 三个操纵变量必须正交

⛔ **频率、间隔、显著性要能独立操纵**，否则 [N5 第二组](../suites/n5-consolidation.md)
分不出系统靠的是哪一个。

具体地：世界里要有「高频但分散」「高频但集中」「低频但显著」这些组合，
每个格子都要有足够的事实量。**「显著的事情通常也发生得更频繁」这种自然相关，
在这个世界里必须被打断**——否则显著性的贡献永远混在频率里读不出来。

### 需求概率是 N5 的 ground truth

⭐ **每条事实带一个「未来 t 时刻还会被查询」的概率**，
它由世界的生成过程直接定义，因此是可对账的真值。
[N5](../suites/n5-consolidation.md) 的全部判分建立在它上面。

<a id="need-probability"></a>

### ⛔ 需求概率不要自己编

自己拍一个分布，等于**自己定义了什么叫「该记住」**——那就成了自证：
我们说该记住的，正好是我们的判分标准说该记住的。

做法照抄 Anderson & Schooler (1991)：**从真实语料里测出需求概率曲线**。
他们用的是报纸标题、亲子对话、邮件的复现统计，测出的保持函数是幂律，
**解释了 93% 的方差**。

对 agent 场景，对应的真实语料是**真实的会话日志 / 工单流 / 提交历史**——
从中测出「一条信息在首次出现后 t 时间还会被再次引用的概率」，
拿这条经验曲线去驱动世界生成。

这样世界的统计结构**有外部效度**，而不是一个我们说了算的参数。

⚠️ 代价：那份经验曲线本身**要进[结果报告](../report.md)**，
和世界清单、种子并列。换一份语料就是换了一把尺子，不写下来两次跑不可比。

## 负载从哪来

世界会变，但**谁在这个世界里干活**是另一个问题。两种负载后端：

| 后端 | 产出 | 用于 |
|---|---|---|
| **合成** | 由事件流按清单与种子生成 | 默认档。可复现性最好，统计结构完全可控 |
| **agent 宿主** | 真实的工具调用 / 文件编辑 / 会话轨迹 | 检验合成负载是否失真 |

agent 宿主档目前指向 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)，
⛔ **钉死版本、进程外调用，源码不进本仓库**（[原则④](README.md#p4)）。

⚠️ **两档的可复现性不同，必须分开报。** 合成档同清单同种子可复现；
agent 宿主档做不到逐次一致——它的价值是**外部效度**，不是可复现性。
⛔ 拿宿主档的数去和合成档的数比较是错的。

## 复现

世界由一份声明式清单构造，连同随机种子一起进[结果报告](../report.md)。
**同一份清单 + 同一个种子必须产出可复现的世界。**
否则两次跑的差可能全部来自世界本身，而不是被测系统。

「逐字节相同」这个说法要收紧一点，因为文件树不只有内容：

| | 怎么钉死 |
|---|---|
| 内容 | 清单直接给定，或由种子确定性生成 |
| 路径与顺序 | 按字典序物化 |
| mode | 清单给定，默认 `0444`（只读） |
| **mtime / atime** | ⛔ **全部设为世界时钟的起始时刻**，不是物化时的真实时间 |
| 时钟起点 | 清单给定的固定 RFC3339 |
| **事件流** | 由种子确定性生成；事件的内容、时刻、显著性标记全部可复现 |
| **需求概率曲线** | ⛔ 经验曲线的**来源语料与拟合参数**一并进报告，不只进代码 |

⚠️ **mtime 是最容易漏的一个。** 不钉死的话，两次物化出的树内容相同、
`stat` 结果不同；而「时间流逝」正是一类变更，一个去读 mtime 判新鲜度的系统
会因此在两次跑之间给出不同答案——差值全部来自 harness，不来自它。

复现校验的口径是上一节的**规范化序列化哈希**加上一次 `mtime` 全等比对，
不是逐字节 `diff -r`。
