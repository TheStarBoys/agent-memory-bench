# 有状态的世界

> **状态：草案。** N1 依赖它。没有这一层，[对现实求值](../suites/n1-reality.md)
> 就退化成又一道阅读理解题。

## 它解决什么

公开题库是静态的：语料给定、问题给定、答案给定。
于是**「记忆是否仍然为真」这个问题根本无法提出**——没有"现在"，只有语料。

世界提供的就是那个"现在"：一份 harness 拥有、可以被改变、可以被系统读取的外部状态。

## 三样东西

| | 是什么 | 系统怎么读到 |
|---|---|---|
| **文件树** | 一个目录，harness 物化出来 | 路径 + 内容 |
| **时钟** | 一个可拨动的当前时间 | 注入的"现在" |
| **事实表** | 键值对，代表外部服务/配置的当前取值 | harness 暴露的只读查询 |

三样都**足够朴素**是刻意的：世界越花哨，越容易长成某一家的实现形状，
而那正是[原则②机制中立](README.md)要挡的东西。

## 归属与只读

**世界归 harness 所有。被测系统只读。**

一个能写世界的系统可以靠**改变现实**让自己的记忆重新为真——
那不是通过测试，是把考题改了。

适配器不提供任何写世界的方法，harness 在 `probe` 阶段前后各校验一次世界哈希；
**不一致直接判本次跑作废**，不是扣分。

## 变更不通知

`mutate` 阶段改完世界，**不告诉适配器**。

这是 N1 的全部要害：被告知"世界变了，去查一下"再去查，测的是**执行**；
没被告知还能发现，测的才是**主动检测腐化**。

同一批题因此天然分两档，分开报：

| 档 | harness 行为 | 量的是 |
|---|---|---|
| **触发档** | 调 `audit()` | 给了机会，你查得准不准 |
| **自发档** | 不调，只在下次 `search` 时看结果 | 没人提醒，你自己发现了吗 |

绝大多数系统在自发档上会全军覆没。**那是这一档的意义，不是它的缺陷。**

## 变更的类型

每一类对应一种真实的腐化方式：

| 类型 | 世界里发生什么 | 记忆应当变成 |
|---|---|---|
| **消失** | 文件被删 | 依赖它存在的记忆 → `fail` |
| **改值** | 文件内容/事实表取值变了 | 断定旧值的记忆 → `fail` |
| **新增** | 出现了新文件/新键 | 多数记忆不受影响 → 仍 `pass` |
| **时间流逝** | 时钟前推 | 带有效期的记忆 → `fail` |
| **无关变更** | 改动与任何记忆都无关 | **全部仍 `pass`** |

⛔ **最后一行是这套题的反方向，必须有。**
只考"该 fail 的有没有 fail"，一个把所有记忆都标成 fail 的系统会拿满分。
**误报率和检出率一起报，缺一个这一类就没有意义。**

## 复现

世界由一份声明式清单构造，连同随机种子一起进结果报告。
**同一份清单 + 同一个种子必须产出逐字节相同的世界**——
否则两次跑的差可能全部来自世界本身，而不是被测系统。
