# 2026-09-03 · ⭐ 「同一条臂两个分数」查清了：库里存了两份

> ⛔ **[交接文档](../../HANDOFF.md)里那个未解的头条问题，成因已定位、已复现、已修、已验证。**
> `mem0_raw` 那个 0.474 不是抖动，是**库里每条语料存了两份**。
> ⚠️ 不是 embedding，不是限流，不是前臂污染——那些都排掉了，见下。

## 一句话

`reset()` 不清盘 → 上一跑的库还留在 `.external/mem0_raw-store/` →
这一跑再摄入 30 条 → 库里 **60 条，每条两份** →
top-10 里一半是重复条目，去重后只剩 **5 篇**不同文档 →
`evidence_recall` **0.789 → 0.474**。⛔ 全程无异常、无告警。

## 怎么跑的

```sh
python -m amb.cli --bench locomo --convs conv-30 --max-turns 30 --sample all \
  --arms bm25,naive_rag,mem0_raw --no-answer
```

| | |
|---|---|
| 语料 | `conv-30` 前 **30 轮**（点名选的，与[轻量样本那份](2026-09-02-locomo-light-a_mem.md)同一份） |
| 抽样 | `all` → **n=17**，`--sample-seed` 用默认 42；⚠️ `all` 全取，seed 在这里不影响选题 |
| 题库 | LoCoMo `3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376` |
| backbone | `Qwen/Qwen3-8B`，思考关（这一档 `--no-answer`，backbone 只参与摄入） |
| embedding | `Qwen/Qwen3-Embedding-4B`，2560 维 |
| 被测系统 | `mem0 2.0.19`（`mem0_raw` = `infer=False`），隔离 venv |
| 地板线 | `bm25` = 0.789 |
| ⛔ 为什么选这份 | ⚠️ 它是交接文档里那个异常**发生过**的语料——查案要在案发现场 |

⚠️ **这一份不是评测**，是查案存档：⛔ 它要证明的是「那个 0.474 从哪来」，
不是「谁比谁强」。分数在这里当**证据**用，⛔ 不当结论用。

## 怎么抓到的

⭐ 按交接文档说的，先跑小样本真跑一遍（`--convs conv-30 --max-turns 30`）——
**第一次跑就复现了 0.474**。而这次[行为指纹](../../src/amb/runner/phases.py)已经在了，
它把那个数摆了出来：

| | 摄入前 | 库中条数 | 命中 | 有 doc_id | 有区间 |
|---|---:|---:|---:|---:|---:|
| bm25 | — | 30 | 3 | 3 | 3 |
| naive_rag | — | 30 | 3 | 3 | 3 |
| **mem0_raw** | — | **⛔ 60** | 3 | 3 | 3 |

⚠️ 交接文档里写的「条数同为 30」指的是**摄入的文档数**，
⛔ 而没有人查过**库里最后有多少条**。指纹一上线，第一跑就露馅了。

## 成因：两条路，同一个结果

### ① `reset()` 是空操作（主因）

```python
def reset(self) -> None:
    if self._bridge is not None:      # ⛔ setup 阶段这里**永远**是 None
        self._bridge.call("reset")
    self._raw.clear()
```

桥是**懒起**的：`run_one` 在 setup 阶段调 `reset()` 时子进程还没起，
于是这个分支一次都没进过——⚠️ 而 qdrant 的库好端端躺在盘上。

⭐ 三行代码复现（[已固化成测试](../../tests/test_store_hygiene.py)）：

```
第 1 轮：摄入 3 条 → 库中 3 条
第 2 轮：摄入 3 条 → 库中 6 条
```

### ② 快照恢复后被判不可信，却直接摄入到它上面

```python
restored = _try_restore(snap, adapter)     # ⛔ 已经把 30 条拷到盘上了
if restored and not _restore_is_sound(...):
    restored = False                       # ⚠️ 只是「不信它」，没清掉它
for doc in plan.documents:                 # → 30 + 30 = 60
    adapter.ingest(doc)
```

⚠️ 而 `mem0_raw` 的快照**必然**被判不可信：它的原文表当时在进程内存里，
恢复后 `spans` 全空 → 指纹对不上 → 丢弃 → 重摄 → 翻倍。
⛔ 所以这条路径是**每一跑都会踩**的。

## 因果验证：60 条确实会给出 0.474

⛔ 不满足于「同时出现」，离线把这一步单独量了一遍——
同一份 conv-30 前 30 轮，同一批查询向量，只改库里存一份还是两份：

| 库中 | evidence_recall |
|---|---:|
| 30 条（正常） | **0.7941** |
| 60 条（每条两份） | **0.4706** |

⭐ 真跑给的是 **0.474**，离线复算 **0.4706**——对上了。
⚠️ 机制很直白：k=10 的 top-10 里每篇文档占两格，去重后只剩 5 篇。

## 排除掉的那些

| 假设 | 结论 | 依据 |
|---|---|---|
| 前臂污染 | ⛔ 排除 | 交接文档已做：单独连跑 3 次都是 0.789 |
| 抽样 | ⛔ 排除 | 同上 |
| 供应商限流 | ⛔ 排除 | 无 429，重试计数为 0 |
| **embedding 端点不确定** | ⚠️ **真的存在，但不是成因** | 见下 |
| 库变大让摄入变慢 | ⛔ 排除 | 实测 10 条进空库 1589ms/条，进已有 10 条的库 966ms/条——不慢 |
| 「摄入慢一倍」是成因 | ⛔ **是巧合** | 见下 |

### ⚠️ 顺带查实：embedding 端点**不是确定性的**

同一句话连嵌 5 次，⛔ 得到**两种**不同的向量：

```
0: sha=b2fdd23d8073   1: sha=c2cb1c649164   2: sha=b2fdd23d8073
3: sha=c2cb1c649164   4: sha=c2cb1c649164
0 vs 1 余弦 0.999917629538   maxdiff 2.3e-03
```

⭐ 这是个此前没人知道的事实：**同一份语料两次摄入，向量不一样**
（多半是后端机型/批处理不同）。⚠️ 每一条走向量的臂都受它影响。

⛔ **但它不是这次的成因**：拿真语料真题量了一遍，
30 篇文档嵌两遍、17 道题各嵌两遍，四种组合的 recall **全是 0.7941**，
逐题比对 **0/17 道题分数变化**。k=10 这个尺度上它扛得住。

⚠️ 所以：端点抖动是**真的**，影响是**测过的**，⛔ 这次**不是它**。

> ⚠️ **补注（同日稍晚）**：「0/17 道题受影响」是在 **30 篇文档**上测的。
> [419 篇那份](2026-09-03-locomo-answer.md)
> 上 `naive_rag` 两跑差了 **+0.007**——⛔ 候选挤了它就露头。
> ⭐ 「向量臂逐位可复现」只在小语料上成立。

### ⚠️ 「摄入慢一倍」是巧合，不是线索

交接文档把 60478ms（正常 30395ms）当成最硬的线索。
⛔ 实测下来它跟成因无关：库变大不会让摄入变慢（上表），
而 embedding 单次调用的实测耗时本来就在 **1805ms～4166ms** 之间跳——**2.3 倍**。
⭐ 那一跑只是同时撞上了端点慢和库翻倍两件事。

## 修了什么

| | |
|---|---|
| `Mem0Adapter.reset()` / `AMemAdapter.reset()` | ⛔ 关子进程**并且**删 store 目录 |
| `run_one` | 快照判不可信后先 `reset()` 再重摄，⛔ 不往它上面叠 |
| `run_one` | ⭐ 摄入前查一次条数，不是 0 就**出声并进报告** |
| 行为指纹表 | ⭐ 加「摄入前」一列，⛔ 必须是 `0 ✓` |
| `Mem0Adapter.finalize()` | 原文表落进 store——⚠️ 快照这才真的能用（省 33s/跑） |
| `embedding.py` | ⭐ 计量 + 出声的退避重试；⛔ 400 不再被重试三次 |
| `wrap_openai_embeddings` | ⭐ 被测系统的 embedding 调用也钉超时、套重试、上计量 |

## 成本：这次修完，反而变快了

⛔ 查案本身没花什么钱（全部 ~$0.02，17 题检索档不挂 backbone）。
⭐ 但修完之后**快照第一次真的能用**了：

| | 摄入耗时 | 说明 |
|---|---:|---|
| 修前 | 70s | ⛔ 每一跑都重摄——快照必然被判不可信 |
| 修后 · 首跑 | 70s | 重摄一次，⭐ 顺带把带原文表的快照存下来 |
| 修后 · 再跑 | **27s** | ⭐ 快照命中，只跑探针 |

⚠️ 摄入的成本数字仍是**存快照那次实测**的（1.26s/条），⛔ 报告里带 † 标着。
⭐ 对 419 轮那份的意义更大：`mem0_raw` 那 72 分钟以前每跑都要再付一遍。
