# 运行结果存档

> ⛔ **每一次值得记的跑都在这里留一份**，连同**当时的版本、抽样、成本**。
> 一份没有这些的结果，读者没法判断它能不能信，也没法复现。

## ⛔ 先读这个：这些系统到底评出来了没有

⭐ **分是跑得出来的，但目前分不出高下。** 这两句话都要说，只说一句都是误导。

### ⛔ 为什么分不开：想测的差，比尺子自己的抖动还小

三层数，一层比一层要紧：

| | 数 |
|---|---:|
| `mem0` 与 `mem0_raw` 的差（想测的信号） | **0.014** |
| n=126 能分辨的最小差（抽样误差） | **0.158** |
| ⛔ `mem0` 同配置跑两次自己跟自己的差（尺子的抖动） | **0.061** |

⚠️ 信号比抽样误差小一个数量级，⛔ 而且**比尺子自己的抖动还小四倍**——
这种情况下再多跑几次也只是在测噪声。

⭐ 三个数都在存档里查得到：差与阈见[重跑档](2026-09-03-locomo-mem0-rerun.md)，
抖动是它与[旧档](2026-09-02-locomo-mem0-full.md)同配置两跑的差（0.730 / 0.669）。

⭐ 抖的是**哪一层**已经查实，不是猜的：

| 臂 | 同配置两跑的差 | |
|---|---:|---|
| `bm25` · `null` | ±0.000 | ⭐ 无 LLM 无向量，逐位确定 |
| `mem0_raw`（关掉 LLM 抽取） | ±0.000 | ⭐ 逐类逐位一模一样 |
| `naive_rag` | ±0.007 | ⚠️ embedding 端点也不确定——⛔ 30 篇语料上测不出来，419 篇才露头 |
| **`mem0`**（开着 LLM 抽取） | **±0.061** | ⛔ chat 端点 `temperature=0` 下 5 次给 **3 种**输出 |

⛔ **工具本身没问题**——不带 LLM 的臂逐位可复现。
⚠️ 抖的是被测系统里那个 LLM 抽取层，而那正是 `mem0` 与 `mem0_raw` 唯一的区别。

### ⭐ 那什么是已经评出来的

这三条不受上面那些影响：

| 结论 | 凭什么 |
|---|---|
| ⭐ **`mem0` 的存储/检索层等价于朴素 RAG** | `mem0_raw` 与 `naive_rag` 逐类几乎完全相同——[63 题](2026-09-02-locomo-first.md) · [17 题](2026-09-02-locomo-light-a_mem.md) · [126 题](2026-09-02-locomo-mem0-full.md) · [126 题重跑](2026-09-03-locomo-mem0-rerun.md) **四次独立复现**。⛔ 它的价值全在 LLM 抽取层 |
| ⭐ **抽取层贵 28 倍** | 每条摄入 `mem0` 10.03s vs `naive_rag` 0.358s。⚠️ 这个差远大于任何噪声，⛔ 不需要更多题就成立 |
| ⭐ **检索名次不能当回答名次** | [回答档](2026-09-03-locomo-answer.md)里检索第 1 的 `mem0` 掉到第 4，检索第 3 的 `naive_rag` 升到第 1 |

⚠️ 注意这三条的形状：**要么是「相等」，要么是数量级的差，要么是名次翻转。**
⛔ 都不需要分辨小差距——那正是它们在这个题量下仍然站得住的原因。

### ⛔ 要真评出高下，缺的是什么

| 缺什么 | 具体到数 |
|---|---|
| **题量** | n=126 只能辨 ≥0.158。⚠️ 而 `mem0` 与 `mem0_raw` 差 0.014——按[样本量表](../sampling.md)，2 个点要 **9775 题**，⛔ 这个差在这个尺度上本来就说不清 |
| **每个数跑多次取分布** | ⛔ 单次跑出来的不是分数，是一个样本。⚠️ `mem0` 两次 0.730 / 0.669，n=2 estimate 不出方差 |
| **或者把抽取层冻住** | ⭐ `AMB_LLM_CACHE=1`，或命中摄入快照。⛔ 代价是那一跑不是独立测量——它冻住的正是要测的不确定性 |

⭐ **一句话：框架能测了，题量还不够下结论。**
⛔ 现在存档里的数字是**观察**，不是排名——每份存档末尾都写着它得不出什么。

## 一份存档必须带什么

| | 为什么 |
|---|---|
| **外部依赖的实际版本** | ⚠️ 换一个被测系统的版本等于换了被测对象 |
| **backbone 与宿主版本** | 换 backbone 分数会变；换宿主等于换尺子 |
| **抽样策略 + 种子 + 分层分布** | ⛔ 不记的话，两次跑的差可能全来自抽到了不同的题 |
| **语料截断与丢题数** | 截了语料要丢掉证据被截掉的题 |
| ⭐ **每个分的置信区间** | 不带区间的抽样分是在骗人 |
| ⭐ **成本** | 「又快又好」才是好——[原则⑥](../adapters/README.md#p6) |
| **地板线是谁** | ⛔ 绝对分不单独读 |

⚠️ 上面每一项报告都会自动带上，⛔ 存档时不要删。

## ⭐ 一个数字要跑两次才算数

⛔ 2026-09-03 之前踩过：同一条臂、同一语料、同一配置，跑出过两个分
（0.789 / 0.474），而**当时没有任何机制能发现哪一跑不正常**——
成因见[那份查案存档](2026-09-03-duplicate-store.md)。

⚠️ 所以：**同一配置至少跑两次，且对行为指纹**。

```sh
python -m amb.cli … --json out/run-a.json
python -m amb.cli … --json out/run-b.json
python tools/compare_runs.py out/run-a.json out/run-b.json
```

| 对不上的地方 | 说明什么 |
|---|---|
| **摄入前** 不是 `0 ✓` | ⛔ 库里有残留，这一跑的语料是重的——分数直接作废 |
| **库中条数**变了 | ⚠️ 摄入本身不确定（归并型系统会）；⛔ 也可能是残留 |
| **有 doc_id / 有区间**变了 | ⛔ 判分依赖的字段掉了——多半是记账没进 store |
| 只有**分**变了，指纹一致 | ⚠️ 那才是真的随机性，去查 embedding / LLM 那一层 |
