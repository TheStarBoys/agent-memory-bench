# 2026-09-03 · 回答档第一次跑：⛔ 检索到证据 ≠ 答得对

> ⭐ **交接文档第 ④ 项的答案，比它想的更硬**：
> 检索档的名次在回答档里**没有保持**——检索第一的 `mem0`（0.669）
> 在回答档掉到**倒数第二**（0.209），而检索第三的 `naive_rag`（0.642）
> 在回答档是**第一**（0.242）。
>
> ⛔ 但五条臂的差**全都分不开**（n=126 只能辨 ≥0.159）。
> ⚠️ 真正该看的是另外两件事：**编造率**，和**三个类别整类为 0**。

## 怎么跑的

```sh
python -m amb.cli --bench locomo --convs conv-43 --max-turns 419 --sample all \
  --arms null,bm25,naive_rag,full_context,mem0_raw,mem0 --sample-seed 20260902
```

⚠️ 与[同日检索档那份](2026-09-03-locomo-mem0-rerun.md)**只差 `--no-answer`**。

| | |
|---|---|
| 语料 / 抽样 | `conv-43` 前 419 轮，`all` → **n=126**，seed 20260902 |
| 题库 | LoCoMo `3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376` |
| backbone | `Qwen/Qwen3-8B`，思考关，⭐ 摄入与回答**同一个** |
| 答题口径 | ⛔ **英文提示**（题库是英文）——见下，这一条是这份存档的关键 |
| 判分 | ⛔ 逐字比对，不用评委。⚠️ LoCoMo 官方那把是 LLM 评委，**两者不可并列** |
| 喂给 backbone | 每题 top-**5**，⛔ 所有臂一致（否则比的是上下文长度） |
| 摄入 | `mem0` / `mem0_raw` ⭐ 命中快照；`naive_rag` 重摄 |
| 耗时 / 钱 | 33 分钟 / **$0.005**（⚠️ 摄入的 $0.22 在[检索档那份](2026-09-03-locomo-mem0-rerun.md)已付） |
| 地板线 | `naive_rag` = 0.242 |

## 结果

| 臂 | 准确率 [95% 区间] | 宽松准确率 | 该答却弃权 | 正确弃权率 | **编造率** |
|---|---|---:|---:|---:|---:|
| `naive_rag`（地板） | **0.242** [0.18, 0.32] | 0.352 | 0.275 | 0.771 | ⛔ **0.229** |
| `mem0_raw` | 0.220 [0.16, 0.30] | 0.352 | 0.275 | 0.800 | 0.200 |
| `mem0` | 0.209 [0.15, 0.29] | 0.330 | 0.330 | 0.857 | ⭐ 0.143 |
| `bm25` | 0.198 [0.14, 0.28] | 0.264 | 0.440 | 0.857 | ⭐ 0.143 |
| `null` | 0.000 | 0.000 | 1.000 | ⭐ **1.000** | ⭐ **0.000** |
| `full_context` | N/A | | | | ⚠️ 语料 55385 码点 > 预算 24000 |

⛔ **五条臂的差全部分不开**：最大差 0.044，⚠️ n=126 只能辨 ≥0.159。

### ⭐ 检索档的名次没有保持

| 臂 | 检索档 `evidence_recall` | 回答档 `准确率` |
|---|---:|---:|
| `mem0` | ⭐ **0.669**（第 1） | 0.209（第 4） |
| `mem0_raw` | 0.655（第 2） | 0.220（第 3） |
| `naive_rag` | 0.642（第 3） | ⭐ **0.242**（第 1） |
| `bm25` | 0.527（第 4） | 0.198（第 5） |

⚠️ 而且**差距整体塌了**：检索档跨度 0.142，回答档只剩 0.044。
⛔ 两档的数不可互比，但**名次可以比**——它们量的是同一批题。

⭐ 这正是交接文档第 ④ 项要问的：**证据捞得更好，答得不一定更好。**
⚠️ 但 n=126 撑不起「谁更好」的结论，⛔ 它撑得起的只有
「**用检索分给回答档排名是不成立的**」。

### ⛔ 编造率与准确率是反着走的

| 臂 | 准确率 | 编造率 |
|---|---:|---:|
| `naive_rag` | ⭐ 最高 0.242 | ⛔ **最高 0.229** |
| `mem0` / `bm25` | 0.209 / 0.198 | ⭐ 最低 0.143 |
| `null` | 0.000 | ⭐ **0.000** |

⚠️ **捞得越多，编得越多**：`null` 什么都不给，backbone 就老老实实弃权
（正确弃权率 1.000）；给了资料之后，backbone 会拿不相关的资料硬答。

⛔ **所以只报准确率是危险的**：`naive_rag` 在准确率上排第一，
同时在「该弃权却编了」上也排第一。⭐ 这两列必须同屏——
一个见题就编的系统，会在只看准确率的表里显得最好。

⚠️ `null` 这一行是这一档最该看的地板：它证明 backbone 本身不会瞎编，
⛔ **编造是资料喂进去之后才出现的**。

### ⛔ 五个类里三个整类为 0 —— 判别力只剩一类

| 类 | 题数 | 各臂准确率 |
|---|---:|---|
| 4-单跳事实 | 64 | 0.281 ~ 0.328 ⭐ **唯一有区分度的一类** |
| 3-开放域推断 | 5 | 0.200（除 bm25 = 0.000）⚠️ n=5，不可当真 |
| **1-多跳** | 9 | ⛔ **全部 0.000** |
| **2-时间推理** | 13 | ⛔ **全部 0.000** |
| 5-弃权 | 35 | 报正确弃权率，不报准确率 |

⛔ **这一档目前的判别力几乎全部来自「单跳事实」那 64 题。**
⚠️ 两个整类为 0 各有各的原因，**都不是「系统不行」**：

**① 时间推理：构造性不可答。**
[`documents_for()`](../../src/amb/suites/public/locomo.py) 把每一轮变成
`"<说话人>: <正文>"`，⛔ **会话日期没有进摄入单元**。
问 `When did Jon go to a fair?`（gold `24 April, 2023`），
所有臂拿到的资料里根本没有日期，只能答 `Yesterday`。
⚠️ 检索档这一类有 0.571~0.643 的分——**捞对了轮次，但那轮次里没有日期**。
⭐ 这一格恰好把「检索到证据 ≠ 答得对」演示到了极致。

> ⭐ **后续（同日）：已修。** 摄入单元改成
> `"[1:56 pm on 8 May, 2023] <说话人>: <正文>"`，
> 日期从 `session_N_date_time` 拼进每一轮。
> ⚠️ 但**别指望这一格直接变高**：只有 26% 的 gold 原样出现在语料里，
> 其余是推导出来的说法（`The week before 9 June 2023`），
> ⛔ 逐字比对本来就给不了分——那是下面①那把尺的上界，与「资料里没有日期」
> 是两件事。见 [benchmarks.md](../benchmarks.md)。
> ⛔ **语料指纹变了，这一跑的数不可与新跑并列。**

**② 多跳：逐字比对判不了。** 9 题的 gold 多是整句，
⛔ 严格比对必然全灭。⚠️ 宽松准确率也没救回来——见下。

## ⛔ 这把尺子量到的和量不到的

⭐ 严格与宽松的差**就是这把尺的不确定度**，这一档它不小：

| 臂 | 准确率 | 宽松准确率 | 差 |
|---|---:|---:|---:|
| `naive_rag` | 0.242 | 0.352 | ⚠️ **+0.110** |
| `mem0_raw` | 0.220 | 0.352 | ⚠️ **+0.132** |
| `mem0` | 0.209 | 0.330 | +0.121 |
| `bm25` | 0.198 | 0.264 | +0.066 |

⛔ 真值落在这两个数之间的某处。⚠️ 而**名次在两把尺下也会变**：
严格看 `naive_rag` 单独第一，宽松看 `naive_rag` 与 `mem0_raw` **并列** 0.352。
⭐ 所以这一档现在的**唯一**结论是「分不开」，⛔ 不是「谁第一」。

### ⚠️ 建这一档时踩到的：尺子在量语言

共用答题提示原本是中文，而 LoCoMo 是英文。实测后果：

| gold | 中文提示答的 | 英文提示答的 |
|---|---|---|
| `by dancing` | ⛔ `跳舞` | ⭐ `Dancing` |
| `19 January, 2023` | ⛔ `昨天` | `yesterday` |
| `They look graceful` | ⛔ `她觉得他们很优雅。` | ⭐ `They look great!` |

⛔ 逐字比对下这些全判错——**那不是记忆层不行，是尺子在量语言**。
⚠️ 在提示里加一句「用问题所用的语言作答」**没用，反而更差**
（中文答案变多，严格准确率 0.077 → 0.077）。
⭐ 换成英文提示才有用：`bm25` 小样本上 0.077 → **0.154**。

⛔ 答题口径因此成了**跟题库走的受控变量**，进报告抬头——
⚠️ 换提示等于换尺子，两次跑不可比。

## ⭐ 顺带得到的：可复现性分三层

这一跑的检索档与[同日那份](2026-09-03-locomo-mem0-rerun.md)对账，
`mem0` 与 `mem0_raw` **命中了快照**（库被冻住），于是：

| 臂 | 两跑差 | 为什么 |
|---|---:|---|
| `null` · `bm25` | ±0.000 | ⭐ 无 LLM、无向量，逐位确定 |
| `mem0` · `mem0_raw` | ±0.000 | ⭐ **命中快照**——库被冻住，抽取只做过一次 |
| `naive_rag` | **+0.007** | ⚠️ **重新摄入了**——embedding 端点不确定 |

⛔ 这修正了[那份查案存档](2026-09-03-duplicate-store.md)里的一句话。
那里说「端点抖动实测扛得住 k=10，0/17 道题受影响」——
⚠️ 那是在 **30 篇文档**上测的。这次 **419 篇**，候选挤得多，
⭐ 它就露头了：**+0.007**。

⚠️ 量级要说清：`naive_rag` 的 ±0.007 与 `mem0` 的 ±0.061 差一个数量级。
⛔ 但「向量臂逐位可复现」这句话不再成立——**只在小语料上成立**。

⭐ 于是可复现性是三层的：

| 层 | 抖多少 | 冻住它的办法 |
|---|---|---|
| 无 LLM 无向量（`bm25`） | 0 | 不需要 |
| 走向量（`naive_rag`） | ±0.007 @419 篇 | ⚠️ 目前没有——⛔ embedding 刻意不缓存 |
| 走 LLM 抽取（`mem0`） | ±0.061 | ⭐ `AMB_LLM_CACHE=1`，或命中摄入快照 |

## ⛔ 不能从这份结果得出的

| ⛔ 得不出 | 为什么 |
|---|---|
| 「`naive_rag` 回答得最好」 | 最大差 0.044，⚠️ n=126 只能辨 ≥0.159。⛔ 五条臂分不开 |
| 「`mem0` 回答不如朴素 RAG」 | 同上。⭐ 能说的只有「检索名次不能拿来当回答名次」 |
| 「多跳 / 时间推理这两类系统做不到」 | ⛔ 一类构造性不可答，一类判分判不了——**都是尺子的问题** |
| 「准确率约 0.2」 | ⚠️ 严格 0.198~0.242、宽松 0.264~0.352，⛔ 真值在两者之间 |
| 与已发表的 LoCoMo 分数比 | ⛔ 官方用 LLM 评委，我们用逐字比对，**尺子不同** |
| 「`naive_rag` 爱编造是它的缺陷」 | ⚠️ 编造的是 **backbone**，不是记忆层——⛔ 它只是喂了更多资料进去 |

⭐ 能当结论的三条：
1. **检索分不能当回答分的代理**——名次在两档之间会翻。
2. **编造率必须与准确率同屏**——两者在这份数据里是反着走的。
3. **这一档现在只有「单跳事实」一类有判别力**——⛔ 另外两类得先修尺子。
