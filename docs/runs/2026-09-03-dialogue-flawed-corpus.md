# 2026-09-03 · 抽取层实验第 1 段 —— ⛔ 语料造错了，这一跑作废

> ⛔ **这份存档的分数一个都不能引用。** 留着它是因为**它是怎么错的**有价值：
> ⚠️ 两个看上去像「被测系统的性质」的现象，其实全是我们渲染语料的方式造成的。
>
> ⭐ 而它是**在花掉第二跑之前**被抓住的——省下 2.5 小时。

## 怎么跑的

```sh
python -m amb.cli --bench dialogue --condition dense   --arms null,bm25,naive_rag,mem0_raw,mem0
python -m amb.cli --bench dialogue --condition revised --arms null,bm25,naive_rag,mem0_raw,mem0
```

| | |
|---|---|
| 世界 | `dialogue`，24 实体 × 5 属性 = **120 条事实 / 120 道题** |
| 抽样 | ⚠️ 不抽题，全跑；世界 `seed=42` |
| backbone | `Qwen/Qwen3-8B`，思考关，`temperature=0` |
| 墙钟 | **2 小时 45 分**（dense 1h05 · revised 1h40） |
| 外部版本 | `mem0==2.0.19` |
| 存档 | [dense](dlg-flawed-dense-20260903.json) · [revised](dlg-flawed-revised-20260903.json) |

## ⛔ 语料错在哪

为了把每轮凑到 LoCoMo 的 145 字符，第一版把**十条互不相干的一句话拼起来**：

> `alice: 我把上下文补一下，免得后面忘了，文档我更新过了，你有空扫一眼，
> 这个我不太确定，得查一下才知道，刚才顺手看了眼监控，暂时没什么异常，……，
> E00的端口是2424。`

⚠️ 长度检查过了，⛔ **但那不是一轮对话，是一袋句子。**

## ⚠️ 于是两个「发现」全是假的

| 跑出来的现象 | 看上去像 | ⛔ 其实是 |
|---|---|---|
| `mem0` 存 **526** 条 / 喂 240 条（膨胀 2.19×） | 「抽取层不压缩反而膨胀」 | ⚠️ 每个碎句都是一条独立断言——⭐ 抽取层**照实**把它们都记了，它没做错 |
| `naive_rag` top1 **0.133**，`mem0_raw` 0.142 | 「向量检索在对话语料上崩了」 | ⚠️ 一个向量成了十个不相干话题的平均——⭐ 而 `bm25` 靠 IDF 拎得出稀有词，拿到 **0.492** |

⛔ **两条都不是被测系统的性质，是我们渲染方式的产物。**
⭐ 真实对话一轮讲一件事——LoCoMo 那 145 字符是**连贯的** 145 字符。

⭐ **地板线是 `bm25`**，⛔ 绝对分不单独读：这一跑里
`revised` 那一档**没有任何一条被测系统打得过地板**——
⚠️ 但那正是语料缺陷造成的（见上），⛔ 所以连这句都不能当结论。
⭐ `null` 全 0.000 是另一条参照：说明这些题**真的需要记忆**才答得出。

⚠️ `Δ 抽取层 = mem0 − mem0_raw` 在 `revised` 上是 **+0.058 / +0.083**——
⭐ 方向对上了，⛔ 但达不到 0.13，而且只有一跑：**记「测不出」**。

## ⭐ 一个顺带的、与语料缺陷无关的发现

`dense` 上 `Δ = −0.025`（测不出），⛔ 而 [toy 那一跑是 **−0.200**](2026-09-03-native-suites-mem0.md)。
⚠️ 两份语料形态相同（短事实句），⭐ 差别在**干净程度**：
toy 的库里同时有 `E07`（事实）和 `E64_00`（拓扑）两套实体名，`dense` 只有一套。

⛔ **不下结论**（两份语料指纹不同，且各只有一跑），
⚠️ 但 toy 那个 −0.200 现在多了一个更可能的解释：**实体名撞车**，
⭐ 而不是「抽取层在短事实句上不划算」。**这一条要在下一跑里查。**

## ⚠️ 成本

⛔ 「又快又好」才是好——一个记得住但慢得要死的系统没有用。

| 条件 | 臂 | 每条摄入 | 摄入总计 |
|---|---|---:|---:|
| dense | `naive_rag` | 0.422s | 51s |
| dense | `mem0_raw` | 1.187s | 142s |
| dense | `mem0` | 8.150s | 978s |
| revised | `naive_rag` | 0.512s | 123s |
| revised | `mem0_raw` | 1.493s | 358s |
| revised | `mem0` | 15.878s | 3811s |

⭐ **抽取层贵 7 倍**（`mem0` 9.7s vs `mem0_raw` 1.4s）——⚠️ 这个数与语料缺陷无关，
⛔ 三次独立的跑给出同一个量级（[toy](2026-09-03-native-suites-mem0.md) ·
[LoCoMo](2026-09-02-locomo-mem0-full.md) · 这次）。
⚠️ 钱可忽略（$0.002 量级），⛔ 瓶颈全是墙钟。

## ⛔ 不能从这份结果得出的

| ⛔ 得不出 | 为什么 |
|---|---|
| 抽取层的**任何**优劣 | ⚠️ 语料本身有缺陷，且只有一跑 |
| 「向量检索不如 BM25」 | ⛔ 那个差距是十话题平均造成的假象 |
| 「抽取层会膨胀」 | ⛔ 同上，是碎句造成的 |
| 与 `toy` / `LoCoMo` 并排比 | ⚠️ 语料指纹不同 |

## ⭐ 改了什么

| | |
|---|---|
| 一轮 = **一段** = 一个话题 | ⛔ 不再拼接，[有测试守着](../../tests/test_dialogue_corpus.py) |
| 闲聊改写成 36 段连贯短文 | ⚠️ 每段 ≥ 70 字符，⛔ 装载时就拦太短的 |
| ⛔ 修掉一个会静默出错的地方 | `_say` 曾先按长度过滤再挑段落，⚠️ 而当时只有 **2 段**够长——600 条噪声轮会全用那两段，⭐ **等于没稀释，而且不报错** |
| 判据从「贴着中位数」改成「落在四分位区间内」 | ⚠️ 中位数对上而方差为零，同样不像真对话 |

⚠️ **已知偏差照旧写明**：轮长四分位我们是 [119, 133, 137]，
LoCoMo 是 [108, 145, 197]——⛔ 中位数进区间了，但**离散度明显偏小**。
