# 2026-09-02 · 轻量样本 · A-mem 第一次进表

> ⭐ **这一跑证明的是管道，不是机制。**
> n=17，⛔ 只能分辨 21 个百分点；三条对照臂**分数完全一样**——
> 语料太小，检索方式根本不重要。
> ⚠️ 有价值的是**成本那一栏**和它暴露的四个报告层 bug。

## 怎么跑的

```sh
python -m amb.cli --bench locomo --convs conv-30 --max-turns 30 --sample all \
  --arms null,bm25,naive_rag,full_context,mem0_raw,a_mem --no-answer
```

| | |
|---|---|
| 语料 | ⭐ `conv-30` 前 **30 轮**（**点名选的**，不是抽中的） |
| 为什么选它 | 小语料上题目密度最高：0.57 题/轮，是其他对话的 2 倍 |
| 抽样 | `all` → **n=17**，`--sample-seed 20260902` |
| ⚠️ 种子在这里不影响选题 | `all` 全取；⛔ 但仍记下来——换成 `random:N` 时它就决定一切 |
| 题库 | LoCoMo `3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376` |
| backbone | `Qwen/Qwen3-8B`，思考关，⭐ 单次调用超时 120s |
| A-mem | `a-mem 0.2.6`，跑在[隔离 venv](../integrating.md#isolation) 里 |

⚠️ 为什么这么小：A-mem 的[摄入成本随库增长](../../src/amb/adapters/impl/a_mem/README.md#growth)。
60 轮那一版实测 29 分钟才摄入 14 条，⛔ 砍到 30 轮才跑得完（15.7 分钟）。

## 结果

地板线 **`naive_rag` = 0.789**（⛔ 不是 `full_context`，理由见下）

| 臂 | 分 [95% 区间] | Δ vs 地板 |
|---|---|---|
| `naive_rag`（对照） | 0.789 [0.553, 0.919] | 地板 |
| `bm25`（对照） | 0.789 [0.553, 0.919] | ±0.000 |
| `mem0_raw`（被测） | 0.789 [0.553, 0.919] | ±0.000 |
| **`a_mem`**（被测） | **0.526** [0.307, 0.736] | −0.263　⛔ 分不开 |
| `null`（对照） | 0.000 [0.000, 0.184] | −0.789 |
| `full_context`（对照） | 1.000 | ⚠️ **退化**，已排除出判定 |

### ⭐ 三条对照臂分数**完全相同**——这本身是结果

`bm25`（纯词面）、`naive_rag`（向量）、`mem0_raw`（存原文+向量）
在 30 轮语料上一字不差都是 0.789。

⛔ **语料太小，检索方式根本不重要**：什么方法都能在 30 条里找到东西。
⚠️ 所以这个规模**测不出机制差异**——它只能验证管道通不通。

⭐ 对比[同日 126 题那一跑](2026-09-02-locomo-mem0-full.md)：
那里 bm25 (0.527) 与 naive_rag (0.642) 拉开了 0.115。
**差异要够大的语料才显形。**

### ⚠️ A-mem 更差，而且贵 31 倍

| | `a_mem` | `mem0_raw` |
|---|---:|---:|
| 分 | 0.526 | **0.789** |
| 弃权类（n=4） | 0.250 | 0.500 |
| 单跳（n=9） | 0.545 | 0.818 |
| **每条摄入** | **31.26s** | **1.01s** |

⛔ n=17 分不开，**不能说它更差**。⚠️ 但成本那一栏没有统计问题：
**31 倍的摄入代价**，换来的分数在区间上完全没有优势。

## ⛔ 这一跑暴露的四个报告层 bug（都已修）

⚠️ 前三个是**同一个疏忽的三种表现**：我上一轮给 `full_context` 标了「退化」，
却没有把它从**判定**里排除。

| | 问题 | 后果 |
|---|---|---|
| `bd359bb` | 检索档里 `full_context` recall 恒为 1.000 | ⛔ 它不检索，全交出去——分母被绕过 |
| `5584327` | 它以 1.000 **当选地板线** | ⛔ 真实臂全被判「被地板压制·没有存在理由」 |
| `5584327` | 总耗时算出 **938102x** | ⚠️ 地板耗时 1ms，所有比值除以它 |
| `5584327` | 钱那一列**永远空** | `usage()` 在 `close()` 之后调，worker 已退出 |

⭐ 还顺带修掉一个**片状测试背后的真竞态**：
`poll()` 在进程刚退出时可能仍返回 `None`，那一瞬桥会把死进程当活的交出去——
⛔「绝不静默重启」这条保证**在负载下会漏**。

## ⛔ 不能从这份结果得出的

| | |
|---|---|
| ⛔ **「A-mem 比别的差」** | n=17 只能辨 0.211，它的 −0.263 落在区间重叠里 |
| ⛔ **任何逐类结论** | 时间推理 n=4、弃权 n=4、单跳 n=9——⚠️ 三格都不能引用 |
| ⛔ **「检索方式不重要」** | ⚠️ 那只在**这个语料规模**上成立，126 题那一跑就拉开了 |
| ⛔ **A-mem 的成本上限** | 30 条测出 31.26s/条，⚠️ 而它[随库增长](../../src/amb/adapters/impl/a_mem/README.md#growth) |

⭐ **这一跑的价值在于：A-mem 第一次跑通了整条管道**——
隔离 venv、子进程桥、超时、退避、快照、判分，全跑通了。
⚠️ 分数本身不构成任何证据。
