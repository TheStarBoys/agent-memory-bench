# 2026-09-03 · 八类自研套件第一次跑真被测系统

> ⭐ **这一跑证明的是管道，不是机制。**
> 八类套件建好以来只跑过 `bm25` / `null` 两条**对照臂**，
> ⛔ `mem0` / `mem0_raw` / `a_mem` 一次都没跑过。这次补上。
>
> ⛔ **连开三个 bug 才跑通**，三个都是「测试全绿、只在真跑时露头」。
> ⚠️ 其中一个让**这次会话刚建的两道防护网在多主体语料上整个失效**。

## 怎么跑的

```sh
python -m amb.cli --bench toy --arms null,bm25,naive_rag,mem0_raw
```

| | |
|---|---|
| 世界 | `toy`——⚠️ **自造的**，172 篇 / 2229 字符 / 平均 13 字符每篇 |
| 主体 | ⭐ **多主体**（alice · bob）——⛔ 这正是 LoCoMo 没有的，也是三个 bug 的现场 |
| backbone | `Qwen/Qwen3-8B`，思考关 |
| 被测系统 | `mem0 2.0.19`（`mem0_raw` = `infer=False`） |
| 抽样 | ⛔ **不抽样**：toy 的题目是写死的，全部跑（`seed=42` 只用于建世界，不选题） |
| 地板线 | 各套件不同——⚠️ 见下表，⛔ 有两个套件对照组全部「不支持」，**无地板线** |
| 耗时 / 钱 | 18 分钟 / 约 $0.001 |
| ⛔ 没跑 | `mem0`（开抽取，约 +29 分钟）· `a_mem`（[成本超线性](2026-09-02-locomo-light-a_mem.md)） |

## ⛔ 先说三个 bug——它们比分数重要

### ① `principal=None` 被当成「用默认主体」

```
ingest: user_id = principal or default → 文档带 alice → 存进 user_id=alice
search: user_id = principal or default → 套件不传     → 查 user_id=amb
count:  固定 filters={"user_id": default}            → 恒返回 0
```

⛔ 而 `bm25` / `naive_rag` 的语义是**不过滤**。`mem0_raw` 因此全线 **0.000**，
⚠️ 且**不报错**——它看起来就像「这个系统很差」。

⭐ **LoCoMo 的文档 principal 全是 `None`**，所以这个 bug 在 LoCoMo 上
永远不会出现。⛔ 换一份语料才照出来。

⚠️ **最要紧的不是那几个 0**：`count()` 正是[行为指纹](2026-09-03-duplicate-store.md)
与「摄入前有没有残留」两道防护网的读数来源——
⛔ 它在多主体语料上恒返回 0，**那两道网整个失效**。

### ② 修好①之后，N4 让整条臂跑挂

```
BridgeError: Storage folder …/qdrant is already accessed by another instance
```

N4 第 3 步「重开——重启即现原形」会 rebuild 第二个实例指向同一个 store，
而 mem0 用 Qdrant **本地模式**，同一目录不许两个客户端并存。

⚠️ 修①之前为什么不崩：那时 search 查不到东西，第 1 步 `delete` 拿到空列表
就 `return "none"`，**根本走不到第 3 步**。⛔ 库一有数据就撞锁。

⛔ 后果是整条臂判「跑挂了」——**评测框架的缺陷被记成了被测系统的失败**。

### ③ 顺带：`_pre_ingest` 那一列在这一跑之前是假的

①的直接后果。⭐ 修完之后这一跑四条臂的「摄入前」全是 `0 ✓`，
⚠️ 而修之前 `mem0_raw` 那一格显示的 0 是**因为 count 恒为 0**，不是因为库干净。

## 结果

| 套件 | `null` | `bm25` | `naive_rag` | `mem0_raw` |
|---|---|---|---|---|
| `retrieval` top1 | 0.000 | 0.750 | **1.000** | **1.000** |
| `qa` 准确率 | 0.000 | 1.000 | 1.000 | 1.000 |
| `n2` 精确匹配率 | ⛔ 不支持 | 1.000 | 1.000 | 1.000 |
| `n5` 正确保留率 | 0.000 | 1.000 | 1.000 | 1.000 |
| `n6` 可达性 fan4 | 0.000 | 1.000 | 0.958 | 0.958 |
| **`n4` 隔离等级** | ⛔ 不支持 | **无** | ⛔ 不支持 | ⭐ **过滤级** |
| `n8` 未归纳 | 1.000 | 1.000 | 1.000 | 1.000 |
| `n1` · `n3` · `n7` | ⛔ 不支持 | 部分 | ⛔ 不支持 | ⛔ 不支持 |

### ⭐ 唯一给出真实差异的一格：N4 主体隔离

| 臂 | 到哪一级 | 说明 |
|---|---|---|
| `bm25` | **无** | ⚠️ 它不声明 GOVERNANCE 的隔离，`search` 不按主体过滤 |
| `mem0_raw` | ⭐ **过滤级** | 它按 `user_id` 过滤得住，⛔ 但只到过滤层，**没到授权层** |
| `naive_rag` · `null` | ⛔ 不支持 | 未声明 GOVERNANCE——⚠️ **不是 0 分** |

⭐ **这是这一跑唯一站得住的结论**，而且它不需要统计功效：
隔离等级是**分类判定**，不是打分。
⚠️ 也正是[公开题库零覆盖](../suites/README.md)的那类能力。

### ⛔ 其余几类：toy 世界太小，全部打满

`retrieval` / `qa` / `n2` / `n5` 上 `naive_rag` 与 `mem0_raw` **一模一样**，
且大多是 1.000。⚠️ 172 篇 13 字符的短文档，什么方法都能找到。

⭐ 这跟[轻量 17 题那次](2026-09-02-locomo-light-a_mem.md)是同一个现象：
**语料太小，检索方式不重要**。⛔ 这个规模测不出机制差异。

⚠️ `n6` 的 `fan4=0.958` vs `bm25` 的 `1.000` 是唯一的非满分格——
⛔ 差 1 题，⚠️ 不可当真。

### ⛔ N8 归纳：全员「未归纳 = 1.000」，包括对照臂

四条臂**没有一条**归纳出规律。⚠️ 这不是「系统都不行」的证据——
⛔ 当一个套件对所有臂（含 `null`）给出同一个值时，
**先怀疑题，不是先怀疑系统**。⭐ 这一类需要单独查，本次不下结论。

> ⭐ **后续（同日）：查出来了，是我们的题，不是系统。**
> 答题提示要求「资料里没有答案就回答『资料未提及』」，
> 而 ①③ 问的是**故意留出来、没进语料**的个体——⛔ 于是 backbone 老实弃权，
> 而解析器只认「是/否」，四条臂结构上不可能得分。
> ⛔ 诚实弃权与归纳外推是**相反的要求**，一套提示不可能同时满足。
> 已改成「语言跟题库走，口径变体跟**套件**走」，
> 见 [N8](../suites/n8-induction.md#这一类必须换答题口径)。
> ⚠️ **这一格的数字作废**，⛔ 不可与修复后的跑并列。

## ⛔ 不能从这份结果得出的

| ⛔ 得不出 | 为什么 |
|---|---|
| 「`mem0_raw` 与 `naive_rag` 一样好」 | ⚠️ 题量太小，五类里四类双方都打满 1.000 |
| 「`mem0_raw` 治理能力强」 | ⭐ 只能说到**过滤级**，⛔ 没到授权级；⚠️ 且探针题只有一条 |
| 「`bm25` 治理不如 mem0」 | ⛔ 它压根没声明那个能力——[不支持 ≠ 0 分](../adapters/README.md) |
| 「N8 说明系统归纳不了」 | ⛔ 全员同值，先查题 |
| 任何**跨题库**的比较 | ⛔ toy 与 LoCoMo 的数不可互比 |
| 外部效度 | ⚠️ toy 是**自造**的世界，⛔ 没有第三方背书——这是自研套件的固有代价 |

⭐ 能当结论的两条：
1. **八类套件在真被测系统上跑得起来了**——⛔ 但代价是三个 bug，
   全部是「测试全绿、只在真跑时露头」。
2. **N4 隔离等级是这一跑唯一的真实差异**，⭐ 而它是定性判定，
   不需要更多题——这正是自研套件相对公开题库的价值所在。
