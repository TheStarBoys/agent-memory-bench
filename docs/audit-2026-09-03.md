## ⛔ 一、可比性的四个指纹，四个都漏

**同一个形状，四个实例。** 这一族最要紧，因为它让所有「两跑可不可比」的判断失效。

| 指纹 | 漏了什么 | 后果 | 证据 |
|---|---|---|---|
| `world.digest` | ⛔ **全部生成语料** | 172 篇与 434 篇两份存档——文档自己写着「⛔ 与上一跑不可比」——**指纹完全相同** | 实测 `sha256:3e487355e169cea…` 两份一致 |
| `corpus_digest` | `timestamp` · `kind` | ⚠️ **时间是 N5 的自变量**：改了事件流的时间布局而正文不变 → 指纹相同 → 恢复旧库 | `corpus_digest(a)==corpus_digest(b)` = True |
| 摄入快照键 | embedding 模型 · 维度 · `base_url` | 换 embedder 重跑，键**一个字节不变** → 报出旧 embedder 的分 | `ingest_identity()` 只有 `AMB_LLM_MODEL`+thinking |
| LLM 缓存键 | `base_url` | 同名模型换供应商 → 命中上一家的响应 | 键只哈希 kwargs |

⭐ 有一个 `corpus_digest()` 能盖住语料，⛔ **但它只进快照键、不进存档**——
任何自动对账工具（`tools/compare_runs.py`）都漏这一类。

## ⛔ 二、判分层：区间的分母是错的

`src/amb/scoring/metrics.py:724` —— 所有 Wilson 区间都用 `n = len(观测数)`，
⛔ 而**至少 14 个比例指标的真实分母不是它**（准确率的分母是可答题数、
检出率是该 broken 的题数、精确匹配率是给出了区间的题数……）。

那行注释本身就是 bug：`# ⚠️ 用比例还原成功数——分母是观测数，⛔ 不是别的`

**为什么这条排第一**：区间重叠是这个项目**唯一**阻止「声称 A 比 B 好」的机制
（`render.py` 的 `ci.overlaps`）。分母被顶大 → 区间被压窄 → 不重叠 → 直接印显著差异。
⭐ `docs/sampling.md` 那条贯穿全项目的纪律被**从内部废掉了**。

实测：40 题里只有 1 题给了区间且给对了 → 印 `精确匹配率=1.000 [0.912, 1.000]`，
⛔ 真实证据是**一次观察**，正确区间是 `[0.05, 1.00]`。

同族三条：
- ⛔ **没有区间时，报告静默转为无条件声称差异**——方向正好反了，没区间应当**拒绝**声称
- ⛔ bootstrap 的**零宽区间**被读成「一定分得开」
- ⚠️ `扇形退化斜率` 因为名字里有个「率」被当成比例，配上 Wilson；同源的 `可达性增益` 走 bootstrap ——**两个同类量走了两条路**

## ⛔ 五、N5 的 ground truth 塌成了一个二值

`events.py` 开篇声明「⛔ 三个操纵变量必须正交：频率 · 间隔 · 显著性」。
设计确实正交，⛔ **但由它导出的真值不是**：

```
(1, 'once',        *)  该留 0/6     (3,  'massed',      *)  该留 0/6
(3, 'distributed', *)  该留 6/6     (10, 'massed',      *)  该留 0/6
(10,'distributed', *)  该留 6/6
```

⛔ **`should_keep ≡ (间隔 == distributed)`。频率与显著性的贡献严格是 0。**
频率从 1 涨到 10、显著性从 False 到 True，**一条都没能翻过阈值**。

`保留追踪度`（headline）读作「保留行为是否追踪需求概率」，⚠️ 实际是一道二值题。
`因子_频率` / `因子_显著性` 两行算得出来，⛔ 但它们对应的真值差异**并不存在**。

⭐ `topology.py` 的 `FanTooWide` 是**对的做法**：要不到就大声抛。
⛔ 同一个仓库里另外四个旋钮是静默截断的：

| 旋钮 | 行为 |
|---|---|
| `attrs_per_entity` | ⛔ 静默封顶在 **6**：传 8 或 20 都得到与 6 **逐字节相同**的语料 → 指纹相同 → 命中旧快照，而报告标题写着新参数 |
| `cues_per_fact` | 静默截断到 3 |

| `factgraph(depth=1)` | 产出 **0 道题**，判分器给出 `status=scored` + 一整排 0.000 |

⚠️ `min_chars` 是我这次会话写的。

## ⭐ 查过且干净的（覆盖面）

- **N6 native** —— 最近那次修复是真的：`designation` 与原句不共字，七档等量（每档 16 条），
  bm25 拉出完整梯度（0.688 → 0.000），斜率 −0.151。⭐ **全仓库做得最扎实的一个生成器**。
- **`_say` 的退化 bug 真修好了** —— 36 段闲聊全部 ≥93 字符、**36 段全部被用到**，
  使用次数 3~23 分布平坦，三条硬约束（无数字 / 无实体名 / 无属性词）实测全过。
- **跨进程确定性** —— `PYTHONHASHSEED` 随机化 3 次，五个生成器的指纹逐次相同；
  无任何依赖 `set` 迭代序 / `dict` 顺序 / `hash()` 的路径。
- **三态 / 四态纪律** —— `Unsupported` 绝不返回空列表假装做过；
  `crashed` / `not_applicable` / `harness_fault` 三段分离且从对比表剔除。

- **`registry` / `chunking` / `WorldGuard` / `Ledger` / `materialize↔digest` 往返** —— 逐条核过，正确。
- **`not_publishable` 通路**（direct 档）—— 套件 → `_finish` → `render.publishable()` 全程没断。
- **作废标注**做对了 3/4 处（dialogue 作废档、toy 语料变更、LoCoMo 日期变更、N8 口径变更）。
