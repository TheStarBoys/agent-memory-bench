# 记忆系统对 LLM 的要求：一个可以直接量的判据

> ⭐ **提示预算就是对模型的要求。**
> 一个抽取提示 8000 token 的系统，等于假设你有个又快又能吃长上下文的模型。
> ⚠️ 那不是它「更聪明」，那是它把成本转嫁给了 backbone。

## 怎么量

⛔ 不用跑，读源码就能量：找到它每条摄入要发的**系统提示 + 用户提示**，数 token。

```sh
python tools/measure_prompt_budget.py mem0
```

## 实测（2026-09-02）

| 系统 | 抽取提示 | 相对 | 备注 |
|---|---:|---:|---|
| **mem0** | **8413 token** | 30× | `ADDITIVE_EXTRACTION_PROMPT`，⛔ **写死，无配置开关** |
| A-mem | 668 token | 2.4× | 记忆演化提示 |
| **MemoryOS** | **280 token** | 1× | `KNOWLEDGE_EXTRACTION`（system+user） |

⚠️ mem0 实测每条摄入 **24–86 秒**（Qwen3-8B）：
一次调用读 8009 token、生成 549 token，吞吐 23 tok/s。

⭐ **8413 token 不是可选项**——mem0 把它写死在 `main.py:942`，
⛔ 换掉就不是 mem0 了。

## 这个判据说明什么

| | |
|---|---|
| ⭐ **能不能用小模型** | 8000 token 的提示在小模型上既慢又容易跑偏 |
| ⭐ **单条成本的下界** | 提示是每条都要重付的固定成本 |
| ⚠️ **对上下文窗口的要求** | 8000 token 提示 + 已有记忆 + 新内容，很快撞窗口 |

⛔ **这不该只是选型参考——它是[原则⑥](adapters/README.md#p6)要报的东西。**
一个系统若只在大模型上跑得动，那是它的真实约束，
⚠️ 读者需要知道，而不是看到一个「它准确率更高」就完了。

## ⚠️ 接入成本的另一半：依赖冲突

`pip install MemoryOS==2.0.32` 实测：

- ⛔ 把 `openai` 从 2.x **降级到 1.109**，连带破坏其他依赖
- ⛔ 装完**没有可 import 的模块**（打包问题）

⚠️ 这类问题与提示预算同样是接入成本，⭐ 都该在选型时量，
⛔ 而不是接到一半才发现。
