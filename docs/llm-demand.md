# 记忆系统对 LLM 的要求：怎么量才算量准了

> ⚠️ **本文最初只量提示预算，结论被实测推翻了。**
> 按提示预算，A-mem（668 token）该比 mem0（8413 token）便宜一个数量级；
> ⛔ 实测 A-mem 反而**更慢**。原因见下——量少了两项。

对 LLM 的要求要三项一起看，缺一项就会得出反的结论：

| 量什么 | 为什么不能只看前一项 |
|---|---:|
| ① **提示预算**（输入） | 每条摄入都要重付的固定成本 |
| ② **输出 token** | ⭐ 思考型 backbone 上，输出**远大于**输入——实测 252 进 / 780 出 |
| ③ **每条摄入打几次、随库增长吗** | ⛔ 库越大越贵的系统，小样本量出来的成本会**系统性偏低** |

---

## 实测（2026-09-02，Qwen3-8B @ siliconflow，temperature=0）

### ① 提示预算：读源码就能量，不用跑

```sh
python tools/measure_prompt_budget.py mem0
```

| 系统 | 抽取提示 | 相对 |
|---|---:|---:|
| **mem0** | **8413 token** | 30× |
| A-mem | 668 token | 2.4× |
| **MemoryOS** | **280 token** | 1× |

⭐ mem0 那 8413 token **不是可选项**——写死在 `main.py:942`，⛔ 换掉就不是 mem0 了。

### ② 输出 token：⭐ 真正的大头

A-mem 摄入一条一句话的文档，实测：

| | 提示 | 输入 token | 输出 token | 耗时 |
|---|---:|---:|---:|---:|
| 第 1 条（空库） | 1410 字符 | 252 | **1566** | 58.3s |
| 第 3 条的演化调用 | 3388 字符 | 680 | **5341** | **203.9s** |

⛔ **输出是输入的 6～8 倍。** 提示只有 680 token 的那次调用花了 204 秒，
因为 Qwen3-8B 是思考型模型，它先想很久再答。
⚠️ 只量提示预算，等于把成本里最大的一块漏掉了。

### ③ 调用次数随库增长

| 摄入第几条 | 打几次 LLM | 耗时 |
|---:|---:|---:|
| 1（空库） | 1 | 58.3s |
| 2 | 2 | 127.9s |
| 3 | 2 | 232.3s |

⭐ A-mem 每进一条新记忆要跟**已有邻居**比对并演化链接，
所以第 2 条起每条要打 2 次，且演化那次的提示随邻居数变长。

⛔ **这一条对[抽样](sampling.md)有直接后果**：
成本随库大小增长的系统，用小样本量出来的**每条成本会偏低**，
⚠️ 不能直接外推到全量。报成本时必须一起报**当时库里有多少条**。

---

## ⛔ 结论：A-mem 不是「便宜的那个」

3 条一句话的文档，全部摄入 **418 秒**，其中 **417.6 秒是 LLM**。
对比 mem0 实测每条 24–86 秒。

| | mem0 | A-mem |
|---|---:|---:|
| 提示预算 | 8413 token | 668 token |
| 每条打几次 | 1 | 1→2（随库） |
| ⭐ 实测每条耗时 | 24–86s | **58–293s** |

⚠️ 提示小 12 倍，实测反而更慢。⛔ **选型不能只看提示预算。**

⭐ 便宜的方向另有其人：真正省钱的是**摄入完全不调 LLM**的系统
（我们的 `naive_rag` / `bm25` / `mem0_raw` 就是这一类，
实测 `mem0_raw` 比 `mem0` 快 21 倍）。

---

## 这些数字进哪儿

⛔ **不是选型参考，是[原则⑥](adapters/README.md#p6)要报的东西。**
一个系统若只在大模型上跑得动，那是它的真实约束——
⚠️ 读者需要知道，而不是看到一个「它准确率更高」就完了。

## ⚠️ 接入成本的另一半：依赖冲突

⭐ 这一项现在**结构上解决了**：被测系统一律装进
[自己的 venv](integrating.md#isolation)，走子进程说话。
⛔ 在此之前踩过两次：

| | |
|---|---|
| `MemoryOS==2.0.32` | 把 `openai` 从 2.x 降到 1.109，连带破坏其他依赖；且装完**没有可 import 的模块** |
| `a-mem==0.2.6` | 依赖 `litellm`，它声明 `openai>=2.20,<3.0`——会把 3.7 降下来 |

⚠️ 隔离之后这不再是「接入成本」，但**每个系统自己那套依赖的版本**
仍然要记进锁文件——它跟被测系统的版本号一样，是结果可复现的一部分。
