# 怎么让贵的系统跑得起来（⛔ 不关 LLM）

> 实测：mem0 摄入 **36.7 秒/条**，占总耗时 **86%**。
> ⛔ 关掉 LLM（`infer=False`）能快 21 倍，但那是**换了个被测对象**。
> 这里说的是**不动被测系统**的办法。

## 三条路，只有两条安全

| | 收益 | 安全吗 |
|---|---|---|
| ⭐ **摄入快照** | 重跑问答**免费** | ✅ 完全安全 |
| ⭐ **LLM 响应缓存** | 重跑同一批语料几乎免费 | ✅ 安全，⚠️ 但要标注 |
| ⛔ **并发摄入** | 理论上 10–20 倍 | ⛔ **不安全——见下** |

---

## ⛔ 为什么并发摄入不能用

摄入是 I/O 密集的（CPU 实测 0.6%，全在等网络），所以并发看起来是白捡的加速。

**⛔ 但对归并型系统它不成立。**

mem0 的 `add()` 要拿新事实和**已有记忆**比对，裁决 ADD / UPDATE / DELETE。
并发时每个调用看到的库状态不同 → **归并决策就变了** →
⚠️ 那不是同一个系统跑得快了，是**另一个系统**。

⭐ 判据很清楚：

> **摄入结果依赖已摄入内容的系统，⛔ 不能并发。**

⚠️ 纯索引型（bm25、朴素 RAG、`mem0_raw`）可以并发——
但它们本来也不慢，⛔ 并发对它们没意义。

---

## ⭐ 摄入快照：贵的那一步只做一次

摄入对**同一份语料 + 同一个系统 + 同一个 backbone** 是确定的。
存下来，重跑问答就免费。

⛔ 快照键必须覆盖所有影响摄入的东西：

```
系统名 + 系统实际版本 + backbone + 语料指纹（含顺序）
```

⚠️ **顺序也算进指纹**——归并型系统对摄入顺序敏感。
⛔ 漏掉任何一项都会拿错快照，而那比慢更糟：**它会静默给出别的系统的分**。

⚠️ 写完才落 `.complete` 标记——⛔ 半截快照比没有更糟。

**适用**：改判分口径、加套件、调抽样——这些都不动摄入。

---

## ⭐ LLM 响应缓存：内容寻址

缓存键是 `(模型, 全部参数, 完整请求体)` 的哈希。
同样的输入本来就该得到同样的输出。

```sh
AMB_LLM_CACHE=1 python -m amb.cli --bench locomo --arms mem0
```

⛔ **默认关闭**——打开它的跑不是一次独立的延迟测量，得有人明确要求。

### ⛔ 两条硬规矩

**① `temperature > 0` 时不缓存。** 那会把随机性冻成一个固定答案——
⚠️ 系统本来会给出分布，缓存让它只给一个点。

**② 缓存命中率进报告。** 命中 90% 的跑测出来的「延迟」不是真延迟。
⛔ 不标出来，「它变快了」会被读成系统变快了。

**⭐ 实测（mem0，`infer=True`，⛔ 没关 LLM）**：

    冷缓存  82.0s   调用 1  命中 0
    热缓存   2.7s   调用 1  命中 1   ⭐ 省下 78 秒，快 30 倍

⚠️ 剩下的 2.7 秒是 embedding——那个不缓存，也不该缓存（它便宜）。

### ⭐ 「缓存为什么没生效」现在自己会说

命中率为 0 有很多种原因，⛔ 不分开记就查不出是哪一种。
现在每条跳过路径都计数，并给出**下一步做什么**：

```
⛔ 1 次调用跳过了缓存（temperature>0×1）
   ——⭐ 被测系统在用采样温度。判分要可复现，
     把它的 temperature 钉成 0（mem0 默认是 0.1）
```

四种情形各有各的说法：

| 情形 | 诊断 |
|---|---|
| 没开 | `设 AMB_LLM_CACHE=1 打开` |
| 采样温度 | ⭐ 上面那条 |
| 一次 LLM 都没调 | `⚠️ 缓存无从谈起` |
| 调了但从不命中 | `⛔ 请求内容每次都不同（提示里带了时间戳？随机 id？）` |

⚠️ **区分「一次都没调」与「调了没中」很要紧**——
前者说明这一档根本不涉及 LLM，后者才是缓存有问题。

⛔ 缓存命中率也进报告首屏：

```
⚠️ **LLM 缓存命中 9/10**——⛔ 这次的延迟数不是独立测量
```

### ⚠️ 一个把我卡了很久的前提

mem0 默认 `temperature=0.1`。因为「⛔ temperature>0 时不缓存」这条规矩，
缓存**静默失效**——命中率恒为 0，**而且没有任何报错**。

⛔ 一个静默失效的优化比没有优化更糟：它让人以为已经优化过了。

⭐ 正确的修法不是放宽那条规矩，是**把 temperature 钉成 0**——
判分本来就要可复现，采样温度不该 >0。⚠️ 缓存能用只是顺带的好处。

**适用**：迭代评测代码、复现历史结果、CI。

---

## ⚠️ 还有一条：换 backbone

换一个更快的 backbone 确实能压时间，⛔ **但它改变的是测量本身**——
不同 backbone 抽出来的事实不同，归并决策也不同。

⭐ 它是**受控变量**：只要所有臂用同一个就公平。
⚠️ 但换了之后，**旧结果与新结果不可比**，backbone 必须进报告。

---

## 怎么组合

| 场景 | 用什么 |
|---|---|
| 第一次跑一个系统 | ⚠️ 老老实实花那个时间——⭐ **那个数字本身是结果**（[原则⑥](adapters/README.md#p6)）|
| 改了判分/套件，语料没变 | ⭐ 摄入快照 |
| 复现历史结果 | ⭐ LLM 缓存 |
| CI | ⭐ 缓存 + 快照 + 只跑便宜的臂 |
| 发布对比结论 | ⛔ **冷跑**——缓存命中的延迟数不能当真 |
