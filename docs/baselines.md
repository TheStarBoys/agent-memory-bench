# 对照组

> **没有对照组，所有分数都读不出意义。** 一个系统在某题上拿 72%，
> 这是好是坏取决于**不装它是多少**。

## 五条对照

它们**都是适配器**，实现同一个 [`Adapter` 协议](adapters/protocol.md)，
住在 `adapters/impl/` 里，走同一条代码路径。
⛔ 对照组用另一套代码跑，数就不可比了——那对照就白做。

| | 是什么 | 位置 |
|---|---|---|
| **无记忆** | 只给当前这一轮，跨会话什么都不留 | 绝对地板 |
| ⭐ **裸宿主** | 不挂记忆插件，只用 [DSH 自带的上下文管理与压缩](../ARCHITECTURE.md) | **真实地板** |
| **朴素 RAG** | chunk + embedding + top-k，就这样 | 廉价地板 |
| **BM25** | 连 embedding 都不要，纯词频检索 | 最廉价地板 |
| **全上下文** | 把全部语料塞进上下文窗口 | 天花板参照 |

### ⚠️ 两档里的同名臂不是同一个东西

| | 直接调库 | 装进 agent |
|---|---|---|
| `host_default` | 一个 `search` 返回空的适配器 | ⭐ **裸 DSH，不挂任何记忆插件** |
| `null` | 摄入即丢弃 | 挂了插件但它什么都不记——⚠️ 区分「没插件」与「插件没起作用」 |

⛔ 两档的数不可互比。

### ⭐ 「裸宿主」才是诚实的地板，不是「无记忆」

不挂记忆插件 **≠ 没有记忆**。DSH 自带最近轮次的工作记忆、
上下文压缩（`ctx.compaction`）、文件引用——**这些本身就是一套记忆策略**。

所以真正要回答的问题不是「你比什么都没有强吗」，而是：

> **你比「让宿主自己压缩上下文」强吗？**

⚠️ 一个跑不赢裸宿主的记忆系统，等于在给 agent 添麻烦。
这条线会很难看，但它是最该报的一条。

### 全上下文是参照，不是目标

记忆系统的意义是**用少得多的 token 逼近全上下文的效果**。
所以天花板要和[成本](adapters/README.md#p6)一起读：
逼近到 95% 而只花 3% 的 token，那是巨大的成功。

⛔ 语料塞不下窗口时，这条线记 **N/A**，不是 0。
[BEAM 的 10M token 档](benchmarks.md)对任何模型都塞不下。

## 唯一的纪律：只有记忆层不同

抄 MemoryData 的对照组注释，它说得最准：

> *same backbone, same embedding model, same answering and judging code.
> **What differs is only the memory layer**, which is the whole point of a floor line.*

⛔ 对照组与被测系统必须共享**一切**：

| 必须相同 | 为什么 |
|---|---|
| backbone 模型与参数 | 差一个模型，分数差的可能全来自模型 |
| embedding 模型 | 只对朴素 RAG 与被测系统都用到 embedding 时 |
| 宿主版本与钉死的 seam | 换 DSH 版本等于换尺子 |
| 提示装配 | 提示不同就是两套实验 |
| 判分代码 | 同上 |
| 世界清单与种子 | 不同的世界不可比 |

**唯一允许不同的是记忆层本身。**

## 报告怎么呈现

⛔ **绝对分不单独出现，必须跟着地板线与增量。**

```json
"locomo": {
  "floor":  { "arm": "host-default", "f1": 0.51 },
  "system": { "f1": 0.72, "Δ": +0.21 },
  "ceiling":{ "arm": "full-context", "f1": 0.79, "达成率": 0.91 },
  "cost_ratio_vs_floor": 3.4
}
```

| 列 | 说明 |
|---|---|
| `floor` | 该档最强的那条地板线，⛔ **不是最弱的**——挑弱的抬高自己 |
| `Δ` | 相对地板的增量。**这才是记忆系统的贡献** |
| `达成率` | 相对天花板走了多远 |
| `cost_ratio_vs_floor` | 贵了几倍。⭐ 与 Δ 一起读 |

⚠️ **Δ ≤ 0 要显式标出来**，不能只是「分低一点」。
它意味着这个系统在这道题上**帮了倒忙**。

## ⭐ N1 的地板线：一个被实测推翻的预测

**原先的预测**是：一个不记东西的 agent 每次重新去读文件，
所以它永远看到当前世界，「记忆过时」这个问题对它不存在，
**裸宿主在 N1 上应当接近满分**。

**实测不是这样**（玩具世界，⚠️ 题量小，只作机制说明）：

| | 检出率 | 误报率 | 弃权率 |
|---|---:|---:|---:|
| `bm25`（摄入时留了原文副本） | **1.000** | 0.000 | 0.000 |
| `host_default`（无记忆层，重读世界） | 0.500 | 0.000 | **0.667** |

原因一句话说得清：

> ⭐ **重读世界告诉你「现在是什么」，不告诉你「你记的东西过期了没有」。**
> 要判断「变了」，你必须记得原来是什么。

拆开看就是两类变更的差别：

| 变更 | 无记忆能不能发现 | 为什么 |
|---|---|---|
| **消失**（文件没了） | ✅ 能 | 读一下就知道不在了 |
| **改值**（内容变了） | ❌ 不能 | 没存过原值，无从比较 |
| **时间流逝** | ❌ 不能 | 同上 |

所以 `host_default` 在改值那一类上诚实地报 `unknown`——
⛔ 而不是猜成 `holds`。**弃权率 0.667 是它的正确行为，不是它的缺陷。**

### 这让 N1 的立论更硬，不是更软

原来的说法是「记忆带来速度，也带来过时风险」——只说对了一半。
完整的说法是：

> **没有记忆，就检测不了记忆的腐化。**
> 记忆既是过时风险的来源，也是发现过时的**唯一凭据**。

⚠️ 但成本这一列仍然要读：`host_default` 每次都重读全部来源，
它的 0.500 是花了全额 IO 换来的。⭐ 一个又快又检得准的系统才是真赢。

## 什么时候跑

| 时机 | 跑哪些 |
|---|---|
| 每次发布结果 | ⛔ **全部五条**，与被测系统同一批次、同一世界 |
| 换 backbone | 重跑全部——地板线随模型变 |
| 换 DSH 版本 | 重跑全部（[换尺子](../ARCHITECTURE.md)） |
| 只加了一个新被测系统 | 可复用同批次的地板线，⚠️ 批次号要对得上 |

⛔ **不得引用历史批次的地板线**。地板线随模型、宿主、世界一起漂，
拿旧地板配新成绩，Δ 就是假的。
