# `recency_window` —— 只有上下文窗口，没有记忆层

**只干一件事**：把最近的内容留在一个固定大小的窗口里，装不下就丢最旧的。
⛔ 不检索、不排序、不压缩、不做任何选择。

## ⭐ 为什么需要它

⚠️ `full_context` 是「全都装得下」那个理想情形——⛔ 装不下就记 N/A。
⭐ 于是**最强的对照臂在最该较量的地方弃权了**。

⚠️ 而真实世界里没有「装不下就不干了」这个选项：一个只有窗口的系统会
**丢东西**，然后带着残缺的上下文继续答。⛔ 记忆层的全部主张就是
「我比那个强」——⚠️ 没有这条臂，那句话没有对手。

| | 装得下 | 装不下 |
|---|---|---|
| `full_context` | ⭐ 真天花板 | ⛔ N/A（弃权）|
| `recency_window` | ⚠️ 与它相同 | ⭐ **丢最旧的接着答** |

## ⭐ 它让「窗口扫描」成为可能

⚠️ 要撑爆一个 128k 的窗口得几千轮对话——⛔ 那是几小时的摄入。
⭐ 而把**窗口**调小，几十轮就进入同一个失效区间：
⚠️ 于是「记忆有没有用」与「语料多大」**解耦**了。

⭐ 扫一遍窗口大小得到的是一条**曲线**。⚠️ 记忆系统的主张是
「窗口缩小时我的曲线不塌」——⛔ 单点看不出这件事。

⚠️ 摄入快照让这条曲线跑得起：⭐ 扫窗口只花探针的钱，
摄入那一笔整条曲线只付一次。

## ⛔ 截断必须说出来

⚠️ 静默截断给出的是一个**假的天花板**——读者会读成
「全都读了还只有这个分」。⭐ 所以 `window_stats()` 报告丢了多少条、
多少字，⛔ 跟着分走到报告里。

## ⚠️ 它不是什么

⛔ 它**不是**一个弱记忆系统：⚠️ 它压根没有记忆层。
⭐ 它是**地板**——任何声称有记忆价值的系统都必须明显赢过它，
⛔ 赢不过就说明那个记忆层没有产生价值。
