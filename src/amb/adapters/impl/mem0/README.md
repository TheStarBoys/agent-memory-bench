# `mem0` —— 第一个真被测系统

⭐ 它把**事实抽取 + 增量归并**当主要问题：LLM 抽事实，与已有比对后
ADD/UPDATE/DELETE。这决定了它在几类题上的形状：

| | |
|---|---|
| ⚠️ `ingest` 会调 LLM | 摄入成本远高于纯索引——⭐ 成本那一栏必须一起读 |
| ⛔ 不声明 `PROVENANCE` | 它返回**抽出来的事实**，不是原文片段，给不出区间 |
| ⛔ 不声明 `REALITY` | 它不对外部世界求值 |
| ⚠️ 声明 `GOVERNANCE` | 它有 `user_id` 过滤 + `history()`——⭐ 但那是**过滤不是授权**，四步探针会测出来 |

⛔ 只走公开接口：`from mem0 import Memory` 是包顶层导出，
不 import 内部子模块、不复制代码（[原则④](../../../../../docs/adapters/README.md#p4)）。

版本由 [`setup`](../../../setup/README.md) 钉死并记录实际装到的那个。

## ⭐ 首跑实测

3 篇中文文档 → 抽出 **4 条**记忆（归并行为）。

| 查询 | 结果 |
|---|---|
| 哪个结构学得慢 | ✅ 命中 `neo` |
| 什么动物晒太阳 | ⛔ 返回 `hippo` / `neo`，**漏了 `cat`** |

⚠️ **输入是中文，抽出来的记忆是英文**（"User finds learning new information…"）——
它的抽取提示做了语言归一。⛔ 这会影响跨语言检索，
也说明 `digest` 不能当原文用（本来也不能——它不声明 PROVENANCE）。

## ⭐ 摄入成本：实测 36.7 秒/轮

在 Qwen3-8B（siliconflow）上逐轮计时，LoCoMo 的对话轮：

| 轮 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| 秒 | 14.7 | 44.4 | 15.5 | **85.8** | 23.3 |

**平均 36.7 秒/轮**（15–86 秒）。外推：

| 语料 | 摄入耗时 |
|---|---|
| 60 轮 | 37 分钟 |
| 1 个对话（369 轮） | **3.8 小时** |
| LoCoMo 全量（5882 轮） | ⛔ **60 小时** |

⚠️ 它每次 `add()` 要多轮 LLM 调用：抽取事实 → 与已有比对 →
裁决 ADD/UPDATE/DELETE。⭐ **这不是 bug，是它的设计代价**——
「事实抽取 + 增量归并」本来就贵。

⛔ 所以跑公开题库时**必须**用 `--max-turns` 限住语料，
⚠️ 而那会丢掉证据被截掉的题（数量进报告）。

⭐ 这正是[原则⑥](../../../../../docs/adapters/README.md#p6)存在的理由：
**一个赢 2 个百分点但贵 100 倍的系统，不写下来就看不出来。**
换一个快得多的 backbone 会改变这个数字——⚠️ 所以 backbone 也进报告。

## ⭐ 两条臂：`mem0` 与 `mem0_raw`

mem0 的 `add()` 有个 `infer` 开关。关掉它，就跳过 LLM 抽取，只存原文 + 向量。

| | `mem0`（infer=True） | `mem0_raw`（infer=False） |
|---|---|---|
| 摄入 | ⛔ **36.7 秒/条** | ⭐ **1.7 秒/条**（快 21 倍） |
| 存的是 | LLM 抽出来的事实 | **原文** |
| `PROVENANCE` | ⛔ 不声明——给不出区间 | ⭐ **声明**——存的就是原文，区间对得上 |
| 归并 | ⭐ ADD/UPDATE/DELETE 裁决 | ⛔ 无 |

⭐ **这两条并排跑，量的就是「LLM 抽取买到了什么、花了多少」。**
⚠️ 这是同一个系统的两种配置，⛔ backbone、embedding、存储全都一样——
差别**只在**那一个开关上。

⛔ 两条臂各用各的存储目录，共用会互相污染。
